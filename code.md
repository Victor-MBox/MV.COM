# MV.COM — документация проекта

Сайт-портфолио Виктора Мацакова (будущий домен victormatsakov.com). Одностраничное React-приложение с клиентским роутингом. Этот файл — опорная точка для дальнейшей работы: архитектура, контент, дизайн-система, соглашения и список незакрытых задач. Обновлять при каждом заметном изменении.

## 1. Стек и команды

| Что | Чем |
|---|---|
| Сборка | Vite 6, `@vitejs/plugin-react-swc` |
| UI | React 19, TypeScript 5 (strict, `verbatimModuleSyntax`, `erasableSyntaxOnly`) |
| Роутинг | react-router-dom 7 (`BrowserRouter`) |
| Анимации | framer-motion (переходы, модалки, галерея), gsap (счётчики, метеоры) |
| Стили | SCSS, CSS-переменные, две темы через класс на `body` |
| Линт | ESLint 9 flat config: `@eslint/js`, `typescript-eslint`, `react-hooks`, `react-refresh` |
| Тесты | Vitest 5 (только данные и утилиты, без DOM) |

```bash
npm ci              # зависимости по lock-файлу (Node 22)
npm run dev         # http://localhost:5173
npm run build       # dist/ (в .gitignore)
npm run preview     # http://localhost:4173, отдаёт dist/ с SPA-fallback
npm run type-check  # tsc --noEmit
npm run lint        # 0 предупреждений — обязательное условие
npm test            # vitest run
```

Перед тем как считать задачу готовой: `type-check`, `lint`, `test`, `build` зелёные.

Две папки с опечатками в исходном проекте оставлены как есть, чтобы не ломать импорты: `cards/infoBloсk` (кириллическая «с») и `cards/setviceCards`.

## 3. Маршруты

| Путь | Страница | Данные |
|---|---|---|
| `/` | HomePage | HOME_SERVICES, PROJECTS (featured) |
| `/services` | ServicesPage — обзор: 7 направлений, компактные карточки услуг | SERVICE_GROUPS, SERVICES |
| `/services/:group` | DirectionPage — SEO-страница направления | getGroup |
| `/services/:group/:service` | ServicePage — SEO-страница услуги | getService |
| `/portfolio` | PortfolioPage — фильтр по категориям | PROJECTS, PROJECT_CATEGORIES |
| `/portfolio/:slug` | ProjectPage — кейс с галереей и лайтбоксом | getProject |
| `/about` | AboutPage — навыки, опыт (аккордеон), процесс | EXPERIENCE, PROCESS |
| `/blog`, `/blog/:slug` | BlogPage, PostPage | POSTS |
| `/contacts` | ContactsPage — каналы с копированием, форма, FAQ | CONTACTS, FAQ |
| `*` | NotFoundPage | — |

Правила:
- Внутренние ссылки только через `Link`/`NavLink`, внешние — `<a target="_blank" rel="noopener noreferrer">`.
- Активный пункт меню считается в `LeftMenu` по `pathname.startsWith(to)` (главная — строгое равенство).
- `ScrollToTop` прокручивает наверх при смене пути; если есть `#hash`, скроллит к элементу с таким id (у секций-якорей стоит `scroll-margin-top`).
- Несуществующий `:slug`/`:group` → компонент возвращает `<NotFoundPage />`.
- Хостинг должен отдавать `index.html` на любой путь (SPA fallback), иначе прямые ссылки на внутренние страницы дадут 404.

## 4. Контент как данные (`src/data`)

Весь текст, цены, ссылки и картинки живут здесь. Чтобы изменить контент, править эти файлы, а не компоненты.

- `services.ts` — ядро раздела услуг.
  - `SERVICE_GROUPS` (7 направлений): `key`, `title`, `short` (одна строка для обзора), `description`, `image`, `audience[3]`, `process[4]` (этапы с картинками), `scheme[]` (узлы схемы), `faq[]`, `categories[]` (связь с категориями портфолио для блока «Примеры работ»).
  - `SERVICES` (32 услуги): `key`, `group`, `title`, `short`, `outcome` (фраза результата), `icon` (имя из `ServiceIcon`), `includes[]`, `priceFrom`, `term`, `stack[]`.
  - `HOME_SERVICES` — три карточки на главной, ведут на страницы направлений.
  - `PRICING_MODELS` — форматы оплаты.
  - Хелперы: `getGroup`, `getService`, `getServicesByGroup`, `getGroupStack`, `groupPath`, `servicePath`, `serviceImage`.
- `projects.ts` — `PROJECTS` (6 кейсов): описание, клиент, роль, стек, `categories`, обложка, галерея, задача/решение/результат, 4 метрики для анимированных счётчиков. `PROJECT_CATEGORIES` выводится автоматически.
- `posts.ts` — `POSTS` с контентом в виде блоков (`p | h2 | ul | quote | code`), `formatDate`.
- `experience.ts` — `EXPERIENCE` (аккордеон опыта), `PROCESS` (4 шага на странице «Обо мне»).
- `contacts.ts` — `CONTACTS` и `CONTACT_LINKS` (единственное место с контактами, используется в меню, соцкнопках и на странице контактов), `FAQ`.

Ключи (`key`, `slug`) — латиница и дефисы, попадают в URL. Тесты в `__tests__` проверяют уникальность ключей и целостность данных — при добавлении полей расширять их.

## 5. Дизайн-система

### Шрифт и темы
- Шрифт `Jura` (Google Fonts, подключён в `_main.scss`), везде `letter-spacing` от −0.02em до −0.06em: чем крупнее текст, тем сильнее.
- Темы: переменные объявлены в `_variables.scss` трижды — `:root` (тёмная по умолчанию), `body.light`, `body.dark`. Новую переменную добавлять во все три блока.
- Тёмная тема первична, светлая проверяется после каждого нового блока.

### Ключевые переменные
| Переменная | Назначение |
|---|---|
| `--bg-primary` / `--bg-secondary` | фон карточек / фон страницы |
| `--bg-banner` | радиальный градиент шапок и баннеров |
| `--bg-cards` | градиент карточек `.card` на главной |
| `--bg-menu-a` | фон активного пункта меню, чипсов, подложек |
| `--bg-svg-steck` | подложка иконок стека и тегов технологий |
| `--border-cards` | основной бордер (#1e1e1e / #ddd) |
| `--btn-border-color` | бордер кнопок и ховер-бордер карточек (#2e2e2e / #dedede) |
| `--text-title` / `--text-primary` | заголовки / основной цвет |
| `--text-body` | **читаемый текст абзацев** (0.68 / 0.78 прозрачности). Использовать для любого текста длиннее одной строки |
| `--text-secondary` | полупрозрачный текст 0.25 — только подписи, теги, второстепенные строки из дизайна главной |
| `--text-decor` | #9f9f9f — ярлыки, крошки, подсказки |
| `--bg-btn-menu_light` | градиент светлой кнопки `btn_light` и монограммы в меню |

Акцентные цвета вне переменных: зелёный статус `#77ea31` (точка «онлайн», галочки, успех формы), синий `#2462ff` и оранжевый `#ff6514` — только в размытых пятнах карточек услуг на главной (`card_color-1/2/3`), красный ошибок `#ff6b4a`.

### Типографика

| Заголовок секции (`.titlerow .title`) | 40px / 600 |

### Сетка и отступы
- Контейнер до 1440px, левое меню 270px (свёрнутое 80px), между меню и контентом 20px.
- Между карточками 20px (компактные плитки 16px), между крупными секциями 50–70px.
- Радиусы: карточки и баннеры 18px, плитки 16px, кнопки и инпуты 10–14px, теги 6–8px.
- Карточка `.card`: 30px внутренних отступов, бордер 0.5px, без ограничения по высоте (`max-height` снят намеренно). Модификатор `card--auto` оставлен для совместимости.

### Готовые классы
- Кнопки: `.btn` (нейтральная, hover-«шторка»), `.btn.btn_light` (светлая акцентная, главное действие), `.btn.btn_dark` (контурная, второстепенное действие), `.link-btn` (текстовая ссылка со стрелкой). Внутри кнопки текст в `<span>` или `<span class="btn__label">`.
- `.chips` + `.chip` (+ `.is-active`, `.chip__count`) — фильтры и якорная навигация.
- `.pageStat` — счётчик в шапке (цифра + подпись).
- `.eyebrow` — ярлык над блоком.
- `.titlerow` — строка «заголовок секции + кнопка справа».
- `.serviceGrid` — сетка 3 колонки для `ServiceTile`.
- `.stackChips` — теги технологий.

## 6. Адаптив

Файл `_responsive.scss`, точки 1200 / 992 / 768 / 560. **Все правила обёрнуты в `body { ... }`** — это намеренно: стили компонентов попадают в бандл после глобальных, и без повышения специфичности переопределения проигрывают. Новые адаптивные правила добавлять внутрь таких же обёрток.

На ≤768px меню становится горизонтальной шапкой (аватар/бренд в строку, пункты прокручиваются), все сетки — в одну колонку, модалка и лайтбокс получают компактные отступы. Проверка: `document.documentElement.scrollWidth` не должен превышать ширину окна на 390px.

## 7. Соглашения по коду

- Табы, одинарные кавычки, без точек с запятой, JSX-атрибуты в одинарных кавычках — как в исходном проекте.
- Типы импортировать через `import type` (требование `verbatimModuleSyntax`). Без `enum` и параметров-свойств конструктора.
- Файл с компонентом экспортирует только компоненты (правило `react-refresh/only-export-components`): хуки и контексты — в отдельные `.ts` (пример: `ContactModalContext.ts` + `ContactModalProvider.tsx`).
- Нельзя вызывать `setState` синхронно в `useEffect` (`react-hooks/set-state-in-effect`). Для сброса формы по новому пропу используется `key` (см. `ContactModal`).
- SVG-атрибуты в JSX в camelCase (`strokeWidth`, `clipPath`).
- Декоративные SVG — `aria-hidden='true'`, у интерактивных элементов есть `aria-label`.
- Картинки вне первого экрана — `loading='lazy'`.
- Анимации: framer-motion для появления/переходов (`whileInView` + `viewport={{ once: true }}`), gsap для числовых и покадровых. Есть глобальный `prefers-reduced-motion`.
- Контактные данные и ссылки — только из `data/contacts.ts`.

## 8. Форма и модалка

`ContactForm` валидирует имя, контакт (e-mail / телефон / @ник), сообщение и согласие, показывает ошибки по полям, состояние отправки и экран успеха. Отправка идёт через `submitContact` в `src/api/contact.ts` — сейчас это имитация с задержкой 900 мс и `console.info` в dev. Для боевого режима заменить тело функции на `fetch` к своему endpoint или сервису форм; интерфейс `ContactPayload` не менять.

Выпадающий список «Что нужно сделать» строится из `SERVICE_GROUPS`/`SERVICES` (optgroup по направлениям). Если `open(topic)` передал значение не из списка, оно добавляется отдельной опцией.

## 9. Как проверять

1. `npm run type-check && npm run lint && npm test && npm run build`.
2. `npm run preview` и прогон в браузере: главная, `/services`, направление, услуга, `/portfolio/atomai` (галерея и лайтбокс), `/about`, `/blog/...`, `/contacts`, несуществующий адрес. Открыть модалку, отправить пустую форму (4 ошибки), заполнить и отправить (экран успеха), закрыть Esc.
3. Переключить тему и просмотреть те же страницы.
4. Ширина 390px: нет горизонтального скролла.
5. В консоли нет ошибок и предупреждений React.

В прошлых сессиях прогон делался скриптом на Chrome DevTools Protocol (headless Chrome + Node 22 WebSocket): открыть страницы, кликнуть элементы через `Runtime.evaluate`, снять скриншоты через `Page.captureScreenshot`. Скрипт в репозиторий не входит, при необходимости пишется заново.

## 10. Принятые решения

- Фото разработчика показывается только на главной. На внутренних страницах в меню — монограмма «VM» с именем и ролью.
- Внутренние страницы должны читаться с первого взгляда: короткие карточки, явные кнопки, картинки между текстовыми блоками, подробности — на вложенных страницах. Обзор услуг не содержит длинных описаний и списков.
- Услуги — три уровня под SEO: обзор → направление → услуга. Карточки направлений на главной ведут на страницы направлений.
- Текст абзацев — `--text-body`, а не `--text-secondary`: исходная прозрачность 0.25 годится только для подписей.
- Страница кейса: одна читаемая колонка, факты одной полосой, этапы списком с разделителями, без карточек в карточках.
- Laravel включён в стек (иконка, навыки, услуги, проекты).
- Цены и формулировки услуг — ориентировочные, владелец сайта правит их сам в `services.ts`; лучше лишняя услуга, чем отсутствующая.
- `dist/` не коммитится. Коммиты и пуш — только по явной просьбе.

## 12. Бэклог

- SEO: у страниц нет собственных `<title>`/`<meta description>`/Open Graph. Нужен хук `useDocumentTitle` или `react-helmet-async` с данными из `data/*`, затем `sitemap.xml` и, желательно, пререндер (SSG) маршрутов услуг и кейсов — SPA индексируется хуже.
- Страницы политик (конфиденциальность, cookies, согласие) и ссылки на них из футера и чекбокса формы.
- Реальный backend формы, защита от спама, уведомление в Telegram.
- Аналитика (Метрика/GA) и цели на отправку формы.
- Файл CV и ссылка на него.
- Реальные изображения и тексты вместо заглушек.
- Хлебные крошки в JSON-LD, `BreadcrumbList`/`Service` разметка для страниц услуг.
- Если понадобится блог побольше — вынести посты в Markdown/MDX вместо объектов.
