# MV.COM — документация проекта

Сайт-портфолио Виктора Мацакова (будущий домен victormatsakov.com). Одностраничное React-приложение с клиентским роутингом. Этот файл — опорная точка для дальнейшей работы: архитектура, контент, дизайн-система, соглашения и список незакрытых задач. Обновлять при каждом заметном изменении. Смысловая часть (кому продаём, какие тексты писать, аудит, план переработки) — в `content.md`; этапы 0–2 плана выполнены 19 октября 2026, этап 3 (реальный контент) за владельцем.

## 1. Стек и команды

| Что | Чем |
|---|---|
| Сборка | Vite 6, `@vitejs/plugin-react-swc` |
| UI | React 19, TypeScript 5 (strict, `verbatimModuleSyntax`, `erasableSyntaxOnly`) |
| Роутинг | react-router-dom 7 (`BrowserRouter`) |
| Анимации | framer-motion (переходы, модалки, аккордеоны, галерея), gsap (счётчики в кейсе) |
| Стили | SCSS, CSS-переменные, две темы через класс на `body` |
| Линт | ESLint 9 flat config: `@eslint/js`, `typescript-eslint`, `react-hooks`, `react-refresh` |
| Тесты | Vitest 5 (только данные и утилиты, без DOM) |

```bash
npm ci              # зависимости по lock-файлу (Node 22)
npm run dev         # http://localhost:5173
npm run build       # dist/ (в .gitignore)
npm run preview     # http://localhost:4173, отдаёт dist/ с SPA-fallback
npm run type-check  # tsc --noEmit -p tsconfig.app.json
npm run lint        # 0 предупреждений — обязательное условие
npm test            # vitest run
```

Перед тем как считать задачу готовой: `type-check`, `lint`, `test`, `build` зелёные. `type-check` обязан указывать на `tsconfig.app.json`: корневой `tsconfig.json` содержит только `references` и `files: []`, поэтому голый `tsc --noEmit` ничего не проверял (так было до 19.10.2026).

## 3. Маршруты

| Путь | Страница | Данные |
|---|---|---|
| `/` | HomePage (концепт D «Типографика») — hero со статусом, строка из двух чисел и колонки для HR, 7 плиток офферов, главный кейс с двумя скриншотами, процесс строками, «Почему со мной», 3 статьи блога, «Для HR» с фото, 4 вопроса с открытыми ответами, CTA | HOME_OFFER_LAYOUT + OFFERS, PROJECTS, POSTS, PROOF, HR_LINE, AVAILABILITY, WHY_ME, HR_BLOCK, FAQ |
| `/services` | ServicesPage — 7 офферов, «Сколько стоит», процесс, 11 вопросов (`#faq`), CTA | OFFERS, PRICING, PRICING_MODELS, FAQ |
| `/services/:offer` | OfferPage — страница оффера по content.md §4.2 | getOffer, SERVICES, PROJECTS |
| `/portfolio` | PortfolioPage — главный кейс широкой карточкой + сетка остальных; фильтры появляются от 8 проектов | PROJECTS, PROJECT_CATEGORIES |
| `/portfolio/:slug` | ProjectPage — кейс по content.md §4.7, техника в аккордеоне | getProject |
| `/about` | AboutPage — страница для найма: резюме, GitHub, стек группами, опыт, принципы, главный кейс | EXPERIENCE, STACK_GROUPS |
| `/blog`, `/blog/:slug` | BlogPage, PostPage — скрыты из меню, маршруты живут | POSTS |
| `/contacts` | ContactsPage — каналы с копированием, форма, 4 вопроса | CONTACTS, FAQ |
| `*` | NotFoundPage | — |

Третьего уровня `/services/:group/:service` больше нет: старые адреса отдают 404 (сайт не в продакшене, редиректы не нужны).

Правила:
- Внутренние ссылки только через `Link`/`NavLink`, внешние — `<a target="_blank" rel="noopener noreferrer">`.
- Активный пункт меню считается в `LeftMenu` по `pathname.startsWith(to)` (главная — строгое равенство). Пункт «Блог» из `MENU` убран.
- `ScrollToTop` прокручивает наверх при смене пути; если есть `#hash`, ждёт появления элемента (до ~1 с, потому что страница монтируется после exit-анимации AnimatePresence) и скроллит к нему. У секций-якорей стоит `scroll-margin-top`.
- Несуществующий `:slug`/`:offer` → компонент возвращает `<NotFoundPage />`.
- Хостинг должен отдавать `index.html` на любой путь (SPA fallback), иначе прямые ссылки на внутренние страницы дадут 404.

## 4. Контент как данные (`src/data`)

Весь текст, цены, ссылки и картинки живут здесь. Чтобы изменить контент, править эти файлы, а не компоненты. Правило контента: один факт — одно место на странице; числа только настоящие; технические термины на страницах для бизнеса — только внутри аккордеонов и блока «Для HR».

- `offers.ts` — **витрина услуг**: `OFFERS` (7 офферов из content.md §4.2). Поля: `key` (URL), `title`, `line` (строка на карточке и подзаголовок страницы), `forWhom` (три слова для /services), `priceFrom`, `priceDetail?`, `term`, `cta` («Обсудить лендинг» — подпись кнопки CTA-баннера, винительный падеж), `audience[3]`, `notFor[1–2]`, `outcomes[5–8]`, `priceFactors[3]`, `notIncluded[]`, `afterLaunch?` (иначе общий `AFTER_LAUNCH`), `faq[3–5]`, `services[]` (ключи из `SERVICES`), `categories[]` (связь с кейсами для блока «Примеры»; нет совпадений — блок скрыт), `tech { stack[], notes[] }` — единственное место с технологиями на странице. Хелперы `getOffer`, `offerPath`.
- `services.ts` — **справочник подуслуг**, не витрина: `SERVICE_GROUPS` (7 направлений: `key`, `title`, `short`) и `SERVICES` (32 подуслуги: `key`, `group`, `title`, `short`, `outcome`, `includes[]`, `priceFrom`, `term`, `stack[]`). Собственных страниц нет: подуслуги перечисляются внутри аккордеона «Как это устроено технически» на странице оффера. Каждая подуслуга входит хотя бы в один оффер (проверяется тестом). Хелперы `getGroup`, `getService`, `getServicesByGroup`. Тип `Faq` объявлен здесь.
- `pricing.ts` — `PRICING_MODELS` (три формата оплаты), `PRICING` (блок «Сколько стоит» из content.md §4.3: `included`, `factors`, `estimate`, `reading`, `supportExample`, `terms`, `notDoing`), `AFTER_LAUNCH`, `BUDGET_RANGES` (вилки бюджета в форме).
- `faq.ts` — единый `FAQ` (11 вопросов, content.md §4.9) с ключами; `HOME_FAQ_KEYS`, `CONTACTS_FAQ_KEYS`, `getFaq(keys)`. Ответ про договор и ИП закреплён тестом — менять только по решению владельца.
- `home.ts` — `AVAILABILITY` (статус в hero, месяц обновлять вручную), `PROOF` (два числа строки доказательства), `HR_LINE` (стек и город для третьей колонки), `HOME_OFFER_LAYOUT` (порядок плиток офферов на главной: `key`, `tone` синий/оранжевый, `wide`; тест проверяет, что покрыты все семь офферов), `WHY_ME` (4 обещания), `WHY_ME_PROOF`, `HR_BLOCK` (текст блока для HR и путь к резюме `/cv.pdf`).
- `projects.ts` — `PROJECTS`: сейчас один реальный кейс `norandoms` (`featured`). Поля: `tagline` (строка в шапке кейса), `line` (строка карточки, без чисел), `highlights[3]` (три факта широкой карточки), клиент/год/роль/срок, `stack`, `categories`, `link`, `cover`, `showcase[2]` (два скриншота для блока главного кейса на главной: большой сверху справа, малый снизу слева), `gallery`, `task`/`solution`/`result` (блок «Коротко», без повторения цифр), `metrics[4]` (единственное место с числами на странице кейса), `status`, `features[]`, `scheme[]`, `process[]` (рендерятся внутри аккордеона). `PROJECT_CATEGORIES` выводится автоматически; `getAdjacentProjects` возвращает `undefined`, если проект один. Цифры NoRandoms актуальны на октябрь 2026 — обновлять вручную.
- `posts.ts` — `POSTS` с контентом в виде блоков (`p | h2 | ul | quote | code`), `cover` необязателен (стоковых обложек нет), `formatDate`.
- `experience.ts` — `EXPERIENCE` (аккордеон опыта), `STACK_GROUPS` (стек группами для «Обо мне»), `PROCESS` (4 шага, единственный процесс на сайте, content.md §4.4).
- `contacts.ts` — `CONTACTS` и `CONTACT_LINKS` (единственное место с контактами: меню, соцкнопки, CTA-баннер, страница контактов, блок HR).

Ключи (`key`, `slug`) — латиница и дефисы, попадают в URL. Тесты в `__tests__` проверяют уникальность ключей офферов, услуг и вопросов, ссылки `services[]` на существующие услуги, полноту полей и отсутствие picsum — при добавлении полей расширять их.

## 5. Дизайн-система

### Шрифт и темы
- Два шрифта (Google Fonts, подключены в `_main.scss`): `Geologica` для заголовков через `--font-title` (правило `h1, h2, h3, .title` в `_main.scss`; у `span`-заголовков плиток `font-family` задаётся явно) и `Golos Text` для текста через `--font-body` (правило `*`). `Jura` убран 19.10.2026 вместе с переходом главной на концепт D. `letter-spacing`: текст −0.01em, заголовки −0.03em, H1 главной −0.04em.
- Темы: переменные объявлены в `_variables.scss` трижды — `:root` (тёмная по умолчанию), `body.light`, `body.dark`. Новую переменную добавлять во все три блока.
- Тёмная тема первична, светлая проверяется после каждого нового блока.

### Ключевые переменные
| Переменная | Назначение |
|---|---|
| `--bg-primary` / `--bg-secondary` | фон карточек / фон страницы |
| `--bg-banner` | радиальный градиент шапок и баннеров |
| `--bg-cards` | градиент карточек `.card` (главный кейс, «Для HR», принципы) |
| `--bg-menu-a` | фон активного пункта меню, тегов, подложек |
| `--bg-svg-steck` | подложка тегов технологий `.stackChips` |
| `--border-cards` | основной бордер и разделители списков (#1e1e1e / #ddd) |
| `--btn-border-color` | бордер кнопок и ховер-бордер карточек (#2e2e2e / #dedede) |
| `--text-title` / `--text-primary` | заголовки / основной цвет |
| `--text-body` | **читаемый текст абзацев** (0.68 / 0.78 прозрачности). Использовать для любого текста длиннее одной строки |
| `--text-secondary` | полупрозрачный текст 0.25 — только теги и подписи из дизайна главной |
| `--text-decor` | #9f9f9f — подписи, крошки, номера шагов |
| `--bg-btn-menu_light` | градиент светлой кнопки `btn_light` и монограммы в меню |
| `--font-title` / `--font-body` | шрифты заголовков и текста (не зависят от темы, объявлены только в `:root`) |
| `--bg-spotlight` | радиальное свечение за фото в блоке «Для HR» |
| `--shadow-screen` | тень скриншотов в блоке главного кейса (в светлой теме легче) |

Акцентные цвета вне переменных: зелёный `#77ea31` (точка «онлайн», галочки в списках «что получите» и «что входит», успех формы), красный ошибок `#ff6b4a`, синий `#2462ff`/`#3795ff` и оранжевый `#ff6514` — размытые пятна-свечения карточек. На главной синий `--accent-blue` работает и как типографический акцент: «под ключ» в H1, текстовые ссылки `.textLink`, номера шагов, подпись кейса, «через два дня» в CTA; синий и оранжевый градиенты заливают две цветные плитки офферов (`OfferTile`). Миксины пятен лежат в `_glow.scss` (`spot`, `spot-blue`, `spot-orange`) и используются в `Card.scss` (`card_color-1/2/3`) и `OfferCard.scss` (`offerCard--glow-1/2/3`, чередуются по индексу карточки). Тот же цвет через `--offer-accent` подкрашивает один элемент иллюстрации оффера.

### Типографика
| Роль | Размер |
|---|---|
| H1 главной (`.homeBanner__title`) | 84px / 600, «под ключ» синим |
| H1 внутренней страницы (`.pageHeader__title`) | 56px / 700 |
| Заголовок секции (`.titlerow .title`, h2) | 40px / 600, −0.03em |
| Заголовок блока внутренней страницы (`.offerPage__h2`, `.project__h2`) | 32px / 600 |
| Заголовок карточки | 24px / 600 (карточки офферов, плитки главной; цветные плитки 28px), 22px (статьи, FAQ, «Почему со мной»), 20px (шаги таймлайна) |
| Крупные числа (строка доказательства, факты кейса) | 40px / 26px, 600, Geologica |
| Абзац | 16–18px, line-height 145–165%, цвет `--text-body` |
| Мелкий текст | 13–15px: цены, сроки, подписи фактов |

Правила против «тяжести» (content.md §6): карточка внутри карточки запрещена — списки внутри секций без бордеров, с разделителями `border-top`; иконки либо акцентные (галочка `#77ea31`, 20–22px, без рамки), либо никакие; ярлыков в верхнем регистре на страницах нет (класс `.eyebrow` удалён, крошки и подписи фактов в обычном регистре); одна светлая кнопка `btn_light` на первый экран; стоковых картинок нет — блок без картинки.

### Сетка и отступы
- Контейнер до 1440px, левое меню 270px (свёрнутое 80px), между меню и контентом 20px.
- Между карточками 16–20px, между секциями 90–100px (`.homeSection`, `.servicesPage__section`, `.offerPage__section`, `.aboutPage__section`), на кейсе 70px.
- Радиусы: карточки и баннеры 18px, плитки 16px, кнопки и инпуты 10–14px, теги 6–8px.
- Карточка `.card`: 30px внутренних отступов, бордер 0.5px, без ограничения по высоте.

### Готовые классы
- Кнопки: `.btn` (нейтральная, hover-«шторка»), `.btn.btn_light` (светлая акцентная, главное действие), `.btn.btn_dark` (контурная, второстепенное действие), `.link-btn` (текстовая ссылка в верхнем регистре со стрелкой). Внутри кнопки текст в `<span>` или `<span class="btn__label">`.
- `.chips` + `.chip` (+ `.is-active`) — фильтры портфолио (появляются от 8 проектов).
- `.titlerow` — строка «заголовок секции h2 + текстовая ссылка справа» (`TitleRow`); сама ссылка — `.textLink` (15px, `--accent-blue`, стрелка в тексте), тот же класс у «Смотреть кейс →» и «Опыт и стек →».
- `.stackChips` — теги технологий (`_main.scss`).
- `.offerGrid` — сетка карточек офферов на /services (две колонки); последняя карточка растягивается на всю ширину ряда, её иллюстрация уходит вправо. `.offerTiles` — сетка плиток главной (три колонки, `offerTile--wide` занимает две).
- `.priceSheet` — таблица «подпись слева / содержимое справа» со строками-разделителями (`ServicesPage.scss`, используется и на странице оффера).

## 6. Адаптив

Файл `_responsive.scss`, точки 1200 / 992 / 768 / 560. **Все правила обёрнуты в `body { ... }`** — это намеренно: стили компонентов попадают в бандл после глобальных, и без повышения специфичности переопределения проигрывают. Новые адаптивные правила добавлять внутрь таких же обёрток.

Главная: H1 84 → 64 (≤1200) → 52 (≤992) → 40 (≤768) → 34px (≤560); плитки офферов 3 → 2 → 1 колонка (широкие плитки и последняя на ≤1200 занимают две колонки); «Почему со мной» и блог 4/3 → 2 → 1; кейс, блок HR и FAQ в одну колонку с ≤992 (фото в блоке HR скрыто); строки процесса на ≤992 — номер и заголовок в двух колонках, текст под ними, на ≤560 — в столбик; строка доказательства на ≤768 складывается в список с разделителями.

На ≤768px меню становится горизонтальной шапкой, все сетки — в одну колонку, `priceSheet` и `aboutStack` складываются в одну колонку, модалка и лайтбокс получают компактные отступы. Проверка: `document.documentElement.scrollWidth` не должен превышать ширину окна на 390px (проверено для всех страниц 19.10.2026).

## 7. Соглашения по коду

- Табы, одинарные кавычки, без точек с запятой, JSX-атрибуты в одинарных кавычках — как в исходном проекте.
- Типы импортировать через `import type` (требование `verbatimModuleSyntax`). Без `enum` и параметров-свойств конструктора.
- Файл с компонентом экспортирует только компоненты (правило `react-refresh/only-export-components`): хуки и контексты — в отдельные `.ts` (пример: `ContactModalContext.ts` + `ContactModalProvider.tsx`).
- Нельзя вызывать `setState` синхронно в `useEffect` (`react-hooks/set-state-in-effect`). Для сброса формы по новому пропу используется `key` (см. `ContactModal`).
- SVG-атрибуты в JSX в camelCase (`strokeWidth`, `clipPath`).
- Декоративные SVG — `aria-hidden='true'`, у интерактивных элементов есть `aria-label`.
- Картинки вне первого экрана — `loading='lazy'`.
- Анимации: framer-motion для появления/переходов (`whileInView` + `viewport={{ once: true }}`), gsap для числовых. `App` обёрнут в `<MotionConfig reducedMotion='user'>`, плюс глобальное CSS-правило `prefers-reduced-motion`. Ховер-подъём карточек, которые анимирует framer-motion, делать через `whileHover`, а не CSS `transform` — инлайновый transform от framer перебьёт CSS.
- Контактные данные и ссылки — только из `data/contacts.ts`.
- Списки внутри `Accordion` сбрасывать от стилей `.accordion__body ul` (маркеры, отступ) через селектор с двумя классами, как в `ProjectPage.scss` и `OfferPage.scss`.

## 8. Форма и модалка

`ContactForm` валидирует имя, контакт (e-mail / телефон / @ник), сообщение и согласие, показывает ошибки по полям, состояние отправки и экран успеха. Поля «Что нужно сделать» (7 офферов + «Другое») и необязательное «Бюджет» (вилки из `BUDGET_RANGES`) стоят в одном ряду. Если `open(topic)` передал значение не из списка офферов, оно добавляется отдельной опцией. Отправка идёт через `submitContact` в `src/api/contact.ts` — сейчас это имитация с задержкой 900 мс и `console.info` в dev. Для боевого режима заменить тело функции на `fetch` к своему endpoint или сервису форм; интерфейс `ContactPayload` (`name`, `contact`, `topic`, `budget?`, `message`) не менять.

Esc закрывает модалку; exit-анимация диалога пружинная (~0.8 с), в автотестах ждать не меньше секунды.

## 9. Как проверять

1. `npm run type-check && npm run lint && npm test && npm run build`.
2. `npm run preview` и прогон в браузере: главная, `/services`, `/services/landing`, `/services/web-service` (с блоком «Примеры»), `/portfolio`, `/portfolio/norandoms` (аккордеон техники), `/about`, `/blog/...` по прямой ссылке, `/contacts`, несуществующий адрес и старый `/services/sites`. Открыть модалку, отправить пустую форму (4 ошибки), заполнить и отправить (экран успеха), закрыть Esc. Открыть модалку со страницы оффера — тема подставлена.
3. Переключить тему и просмотреть те же страницы.
4. Ширина 390px: нет горизонтального скролла.
5. В консоли нет ошибок и предупреждений React.
6. Чек-лист content.md §9: числа не повторяются, ярлыков в верхнем регистре нет, стоковых картинок нет, одна светлая кнопка на первом экране.

В сессии 19.10.2026 всё это делалось тремя скриптами на Chrome DevTools Protocol (headless Chrome `/Applications/Google Chrome.app` + Node 22 `WebSocket`, без зависимостей): `shoot.mjs` — скриншоты всех страниц в двух темах и на 390px с проверкой `scrollWidth`; `interact.mjs` — модалка, форма, 404, блог, тема, якорь `#faq`; `audit.mjs` — повторы чисел, uppercase-ярлыки, запрещённые фразы, число светлых кнопок на первом экране; `clip.mjs` — скриншоты заданных участков страницы (`Page.captureScreenshot` с `clip` и `captureBeyondViewport`), потому что `sips --cropOffset` режет не там. Скрипты в репозиторий не входят (живут в scratchpad сессии), при необходимости пишутся заново по этому описанию: `/json/new` → `Page.navigate` → `Runtime.evaluate` → `Page.captureScreenshot` с `captureBeyondViewport`.

## 10. Принятые решения

- Две аудитории (бизнес и HR) на одном сайте: бизнес-язык по умолчанию, техника на уровень глубже — аккордеон «Как это устроено технически» на кейсе и оффере, блок «Для HR и тимлидов» на главной, страница «Обо мне» как страница для найма.
- Витрина услуг — 7 офферов (`offers.ts`), два уровня `/services` → `/services/:offer`. 32 старые услуги остались справочником подуслуг и источником для аккордеона. 1С-Битрикс — не направление, а одна строка внутри оффера «Поддержка и доработка сайта».
- Один процесс работы на сайт (`PROCESS`, `ProcessList`): на главной, /services и страницах офферов. На «Обо мне» процесса нет.
- Счётчики `NumbersCard` удалены; вместо них строка доказательства под hero с двумя фактами (8 лет; NoRandoms 6 000+ пользователей и 500+ посетителей в день). Третьего числа нет, потому что реального числа проектов нет.
- «Один факт — одно место»: блок «Для HR» и пятый пункт «Почему со мной» написаны без «8 лет» и «6 000+», потому что они уже стоят в строке под hero; `highlights` карточки NoRandoms (18 000+, 92%, февраль 2026) не пересекаются со строкой доказательства; `tagline` и «Коротко» кейса без чисел — числа только в блоке метрик; из подписей галереи и текстов модулей убраны «18 000» и «13».
- Вымышленные кейсы (atomai, fade, nordic-estate, pulse-crm, orbit-studio, greenline) удалены вместе с `resources/portfolio.jpeg`. Пока проект один, портфолио показывает его широкой карточкой без фильтров (фильтры от 8 проектов, `FILTERS_FROM`).
- Фото разработчика показывается только на главной и в шапке «Обо мне». На внутренних страницах в меню — монограмма «VM» с именем и ролью «Full-stack разработчик».
- Картинки только свои: все `picsum` убраны (направления, этапы, услуги, посты, кейсы) — блок без картинки, а не заглушка.
- Крошки, подписи фактов и подписи каналов на контактах — в обычном регистре; верхний регистр остался только у текстовых кнопок `.link-btn`.
- В `FooterBanner` вторая кнопка «Написать в Telegram» ведёт на `CONTACT_LINKS.telegram`; на странице оффера подпись главной кнопки берётся из `offer.cta`.
- Последняя карточка в `.offerGrid` («Для агентств и студий») растягивается на всю ширину ряда — так 7 карточек заполняют сетку из 2 и 3 колонок без дыр.
- Карточки офферов сохраняют свечение исходных градиентных карточек главной (решение владельца после первого прогона) и получили линейные иллюстрации без рамок — акцентные, как разрешает content.md §6 п.2. Чтобы семь карточек не спорили друг с другом, свечение в покое приглушено до 0.4 и разгорается по ховеру. Шапка страницы оффера повторяет иллюстрацию и свечение своей карточки (`offerHeader--glow-N`, индекс оффера в `OFFERS`).
- Визуал добавлен только там, где он держит структуру: свечение и иллюстрации у офферов, таймлайн у процесса, появление блоков при прокрутке (офферы, шаги, «Почему со мной»). Таблица условий, FAQ, стек, контакты и кейс остаются без декора: там работают содержимое и скриншоты.
- Текст абзацев — `--text-body`, а не `--text-secondary`.
- Кейс NoRandoms (norandoms.team) — реальный собственный продукт Виктора. В стеке кейса MySQL и WebRTC указаны по косвенным признакам — при необходимости поправить в `projects.ts`.
- Удалены как мёртвый код: `Skills`, `InfoBlock`, `MyStack`, `TitleSubtitle`, `ServiceCards`, `NumbersCard`, `ShinyText`, `ServiceTile`, `ProcessSteps`, `MeteorsGSAP`, `utils/plural.ts`, `_block-services.scss`, классы `.eyebrow`, `.pageStat`, `.chip__count`, `.card--auto`, переменные `--scale__*`.
- Адаптив: в `_responsive.scss` не использовать `:not(.класс)` для сеток — он поднимает специфичность, и мобильное правило ниже по файлу проигрывает (так плитки офферов оставались в две колонки на 390px). Вместо этого модификаторы `--compact`/`--full`.
- Цены и формулировки офферов — ориентировочные (content.md §4.2 как есть), владелец правит их в `offers.ts` и `pricing.ts`.
- Главная переведена на концепт D «Типографика» из Claude Design (19.10.2026): шрифты Geologica + Golos Text для всего сайта вместо Jura; фото из hero переехало в блок «Для HR»; семь офферов — плитками `OfferTile` с двумя цветными (`web-service` широкая синяя, `integrations` оранжевая, порядок в `HOME_OFFER_LAYOUT`), свечение и иллюстрации остались только на /services; кейс — `ProjectSpotlight` с двумя скриншотами; процесс — строками; FAQ — четыре вопроса с открытыми ответами вместо аккордеона; строка под hero — три колонки (два числа + стек/город/«Опыт и резюме →»). «Один факт — одно место» сохранено: подпись кейса собирается из `client` и `status`, числа — только в `highlights`.
- По концепту на главную вернулся блог: три плитки `PostTile` из `POSTS` под «Почему со мной». Посты пока вымышленные (см. §11) — секция убирается удалением блока в `HomePage.tsx`; из меню блог по-прежнему убран.
- Статус в hero — `AVAILABILITY` = «Беру проекты с ноября» (content.md §4.1), месяц обновлять вручную.
- Кнопка в `TitleRow` заменена текстовой ссылкой `.textLink`, CTA-баннер перерисован по концепту — оба компонента общие, изменение видно на всех страницах. Внутренние страницы (шапки `PageHeader`, карточки /services, таймлайн) к концепту D не приводились — см. бэклог.
