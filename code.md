## 1. Стек и команды

| Что | Чем |
|---|---|
| Сборка | Vite 6, `@vitejs/plugin-react-swc` |
| UI | React 19, TypeScript 5 (strict, `verbatimModuleSyntax`, `erasableSyntaxOnly`) |
| Роутинг | react-router-dom 7 (`BrowserRouter`) |
| Анимации | framer-motion (переходы, модалка, аккордеон, галерея, маски строк, слайдер), gsap (счётчики `CountUp`), lenis (плавный скролл, только главная) |
| Стили | SCSS, CSS-переменные, две темы через класс на `body` |
| Линт | ESLint 9 flat config: `@eslint/js`, `typescript-eslint`, `react-hooks`, `react-refresh` |
| Тесты | Vitest 5 (только данные и утилиты, без DOM) |
| CI / деплой | GitHub Actions (`.github/workflows/ci.yml`, `deploy.yml`) → rsync по SSH на облачный сервер Beget, nginx (`deploy/`); §13 |
| Обработчик формы | `server/` — отдельный npm-пакет: Node 22 (`node:http`, `fetch`) + nodemailer, JS с JSDoc под `checkJs`; POST `/api/contact` → Telegram Bot API и SMTP; на сервере — служба systemd за прокси nginx; §8, §13 |

```bash
npm ci              # зависимости по lock-файлу (Node 22)
npm ci --prefix server  # зависимости обработчика формы (server/package-lock.json) — нужны для type-check и `npm run server`
npm run dev         # http://localhost:5173; /api/* проксируется на обработчик (127.0.0.1:3721)
npm run server      # обработчик формы локально: server/contact.js с переменными из server/.env (образец server/.env.example)
npm run build       # dist/ (в .gitignore); VITE_SITE_URL — из .env.production
npm run preview     # прод-сборка локально
npm run lint        # 0 предупреждений — требование
npm run type-check  # tsc --noEmit
npm test            # vitest run
```

## 7. Соглашения по коду

- Табы, одинарные кавычки, без точек с запятой, JSX-атрибуты в одинарных кавычках.
- Типы импортировать через `import type` (`verbatimModuleSyntax`). Без `enum` и параметров-свойств конструктора.
- Файл с компонентом экспортирует только компоненты (`react-refresh/only-export-components`): хуки и контексты — в отдельные `.ts` (`ContactModalContext.ts` + `ContactModalProvider.tsx`).
- Нельзя вызывать `setState` синхронно в `useEffect` (`react-hooks/set-state-in-effect`): измерения — в `document.fonts.ready.then` / `ResizeObserver` (как `SplitLines`), подписки — через `useSyncExternalStore` (`useMediaQuery`, `useTheme`); сброс формы по новому пропу — через `key`.
- SVG-атрибуты в JSX в camelCase; декоративные SVG — `aria-hidden='true'`; у интерактивных элементов `aria-label`; картинки вне первого экрана — `loading='lazy'`.
- Анимации: framer-motion для появления и переходов (`App` в `<MotionConfig reducedMotion='user'>` + глобальное правило `prefers-reduced-motion`), gsap для чисел. Ховер-подъём карточек, которые анимирует framer, — через `whileHover`, не CSS `transform`.
- Контактные данные и ссылки — только из `data/contacts.ts`; тексты — из `data/*`, в страницах остаются только строки, относящиеся к одной странице (ABOUT, PRINCIPLES, CHANNELS, H1 и H2 с `TODO (владелец)`).
- Новые страницы: `PageHead` → секции `.section > .container` с `SectionHead`; финальный призыв с формой даёт общий футер, своего CTA-блока у страниц нет; только токены 1.0 и компоненты §5; старых классов (`.btn`, `.card`, `.titlerow`) и токенов (`--bg-primary`, `--accent-blue`) в проекте нет — не возвращать.
- Тема: `useTheme` — единый стор (`useSyncExternalStore`); `localStorage.theme` пишется только при ручном выборе; тот же алгоритм продублирован инлайн-скриптом в `index.html` — при изменении ключа или правил менять оба места.
- Lenis поднимает только главная (`useLenis()`); пока открыта модалка или мобильное меню — `lenis.stop()`; `lenis.scrollTo(element)` сам вычитает `scroll-margin-top`.
- У всех элементов `scroll-behavior: smooth` (`_main.scss`), поэтому `window.scrollTo({ behavior: 'auto' })` тоже анимируется: прыжок — только `behavior: 'instant'`. Прокрутку при смене маршрута делать не по смене `location`, а при монтировании новой страницы (`ScrollToTop`): до конца exit-анимации на экране старая страница, и любой скролл двигает её.
- Прокрутку под оверлеем блокирует только `useScrollLock(active)` (модалка, мобильное меню, лайтбокс), не `body.style.overflow`: `overflow: hidden` на `html` (на `body` он делает body контейнером прокрутки — липкая шапка на прокрученной странице уезжает вверх), ширина пропавшей классической полосы прокрутки уходит в `--scrollbar-gap` → `padding-right` у `body` и `right` у `.socialDock` (новым `fixed`-элементам у правого края — так же). Оверлеи с центрированным содержимым — `left: 0; width: 100vw` вместо `inset: 0`: блокировка снимается сразу по закрытию, полоса возвращается во время exit-анимации, и с `right: 0` содержимое съезжало бы. Правила `.lenis-stopped { overflow }` в `_system.scss` нет намеренно — оно прятало полосу без компенсации.
- `backdrop-filter` делает элемент containing block для `position: fixed` потомков — у `TopHeader` фон и блюр на `::before`, панель меню, соцпанель, модалка, курсор и лайтбокс рендерятся порталом в `body`.
- У `motion.div` пропы `onDragStart`/`onDragEnd` — колбэки жеста; нативный DnD ссылок и картинок внутри drag-ленты гасится через `addEventListener('dragstart', preventDefault)` (так было в `WorkSlider`, удалён 21.10.2026).
- `useScroll({ target })` требует смонтированного `target` и не-static контейнера: у `CaseCard` опции передаются только при `wide`, `html { position: relative }` в `_system.scss`.
- Вложенный селектор `&__x` внутри медиазапроса компилируется в ту же специфичность, что и базовое правило ниже по файлу, — для переопределений в медиазапросах добавлять родителя (`&__actions &__theme`).
- Правило `:is(h1, h2, …) * { font-weight: inherit }` не включает h3/h4: иначе UA-bold утекал бы в `.dimAcc__title` внутри `h3.dimAcc__head`; заголовкам явно задан вес 500.

## 8. Форма и модалка

С 21.10.2026 форма первого обращения одна по составу и правилам на всех поверхностях (модалка, `/contacts`, футер): поля `LEAD_FIELDS` — «Как к вам обращаться» (необязательно), «Telegram или почта», «Что нужно сделать» — и обязательное согласие. Правила `validateContact` (`components/leadForm/validate.ts`, тест `leadForm.validation.test.ts`): контакт — почта, @ник или номер, иначе «Укажите Telegram или почту, чтобы я мог ответить»; пустая задача — «Коротко опишите, что нужно сделать»; без согласия — «Нужно согласие на обработку данных». Состояние, снятие ошибок по мере правки и отправка — хук `useLeadForm(topic)`; разметка своя у `LeadForm` (поля-карточки) и `FooterForm` (строки макета). `ContactPayload` = `{ name, contact, message, topic, website? }`: `topic` — контекст, который ставит сайт (название оффера на его странице, формат из блока цен), в текст посетителя он не попадает; `website` — скрытое поле-ловушка для ботов (`TrapField`, общий для обеих форм: `.srOnly`, `aria-hidden`, вне табуляции; человек его не заполняет, непустое сервер молча отбрасывает); намерений, услуги и бюджета больше нет. Инструкция, что прислать (`FORM_COPY.lead`, ТЗ по текстам и SEO) — одна: подзаголовок модалки и лид панели на `/contacts`; в футере её нет, чтобы не повторять на каждой странице.

Согласие (ТЗ «документы, согласия, cookie» от 22.10.2026, §7): подпись чекбокса — «Даю [согласие на обработку персональных данных] для рассмотрения обращения» (`FORM_COPY.consent`, ссылка на `/personal-data-consent` в новой вкладке; клик по ссылке внутри label чекбокс не отмечает — проверено), под ним строка «Как обрабатываются данные — в [Политике конфиденциальности].» (`FORM_COPY.policy` → `/privacy`); разметка общая — `components/leadForm/ConsentNote.tsx` (`ConsentLabel`, `PolicyLine`, `TopicLine`). Ошибка без согласия — «Для отправки заявки нужно согласие на обработку персональных данных» (`role='alert'`). Услуга, с которой открыта форма, показывается строкой «// услуга: Лендинг» над полями (`TopicLine`), в текст посетителя не попадает. После приёма — «Заявка принята. Отвечу по указанному контакту в течение рабочего дня.» и строка «Номер заявки: MV-20261022-XXXXX» (по номеру ищут обращение при отзыве согласия); ошибка — «Не удалось отправить заявку. Попробуйте ещё раз или напишите в Telegram.», введённое сохраняется. Содержимое полей не пишется в localStorage, URL, консоль (в тестовом режиме — только `topic` и `formId`).

Готовность (`data/leadForm.ts`, `api/contact.ts`): обработчик и документы есть (`FORM_DELIVERY_READY = true`, `FORM_ENABLED = true`), а показывать ли форму в публичной сборке, решает сервер (ТЗ §4: не клиентский флаг): при первой подписке один `GET /api/contact/health`; `ready: true` → форма, `ready: false` или 503 → `FormFallback` («Написать в Telegram», почта), нет ответа / не JSON → форма остаётся, сбой покажет отправка. Хук `useFormVisible` (`components/leadForm/useDeliveryReady.ts`) — в `LeadForm`, `FooterForm` и вступлении `/contacts`; на dev-сервере форма видна всегда. Тестовый режим с имитацией (900 мс, сбой — `localStorage.setItem('contact-mock', 'fail')`, метка `FORM_COPY.testMode`) остаётся только на случай выключенного `FORM_DELIVERY_READY`.

Отправка — `submitContact` в `src/api/contact.ts`: POST JSON `ContactPayload` = `{ name, contact, message, topic, consent: true, consentVersion, formId: 'modal' | 'contacts' | 'footer', submissionId, website? }` на `/api/contact` (тот же origin); `consentVersion` всегда подставляется действующая (`CONSENT_VERSION` из `data/legal.ts`), `submissionId` — `crypto.randomUUID()` на одну отправку (после успеха новый): повтор после обрыва сети сервер узнаёт и отдаёт прежний номер без второй заявки. Успех только при 2xx и `{ ok: true }`, возвращается `requestId`.

Обработчик — `server/contact.js` (Node, без фреймворка; чистая логика в `server/lib.js` с тестами): порядок — 503 `not_configured`, если нет канала с содержимым (почта или `TELEGRAM_CONTENT=full`) или папки записей о согласии; 403 `forbidden_origin`, если `Origin` не совпадает с `Host` запроса (за nginx — `$host`, на dev — адрес Vite при `changeOrigin: false`) и не входит в `ALLOWED_ORIGINS`, либо `Sec-Fetch-Site: cross-site`; лимит 5 заявок с IP за 10 минут (`RateLimiter`, в памяти; IP — из `X-Real-IP`); тело до 32 КБ; `parseLead` — те же правила, что `validateContact`, плюс пределы длины (`LIMITS`: имя 120, контакт 200, задача 5000, тема 200, ключ 64), чистка управляющих символов, `consent === true`, `consentVersion` = версии из `server/legal.json`, `formId` из `FORM_IDS`; ловушка `website` → 200 без отправки; повтор `submissionId` (`SeenSubmissions`, окно лимита) → прежний ответ. Дальше серверные `receivedAt` и `requestId` («MV-ГГГГММДД-XXXXX», алфавит без похожих символов), доставка параллельно: почта — nodemailer по SMTP (тема «Заявка с сайта MV-…: <topic | общее обращение>», текст без HTML: номер, время UTC, форма, тема, имя, контакт, задача, страница, строка «Согласие на обработку данных: отмечено, редакция 1.0 (политика 1.0)», `Reply-To` — почта посетителя), Telegram — по умолчанию `telegramNotice` (номер, время, тема, «Подробности — в письме»; имени, контакта и текста нет — ТЗ §8), при `TELEGRAM_CONTENT=full` — полный текст как раньше. Заявка принята, если содержимое дошло хотя бы по одному каналу с содержимым (уведомление не считается); затем строка в `consents.jsonl` (`consentRecordLine`: requestId, receivedAt, formId, consent, consentVersion, consentSha256, policyVersion, page — путь без query, topic, delivered; без имени, контакта и текста), сбой записи — в журнал, заявка остаётся принятой (письмо само содержит номер и редакцию). Очистка журнала — записи старше `CONSENT_RETENTION_DAYS` (180) при старте и раз в сутки, файл переписывается атомарно. Ответы: 200 `{ok:true, requestId}`; 400 `invalid` (+`fields`) / `bad_json`; 403; 413; 429; 502 `delivery_failed`; 503 `not_configured`; `GET /api/contact/health` → `{ ok, ready, telegram, mail, telegramContent, consentLog, versions }`. Переменные — `server/.env.example`: `SMTP_*`, `MAIL_FROM` / `MAIL_TO`, `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID` + `TELEGRAM_CONTENT` (`notice` | `full`), `CONSENT_LOG_DIR` (локально `.data`; на сервере — `STATE_DIRECTORY` от systemd), `CONSENT_RETENTION_DAYS`, `ALLOWED_ORIGINS`, `RATE_LIMIT` / `RATE_WINDOW_MIN`, `LISTEN_HOST` / `PORT`. Содержимое заявок в журнал journald не пишется — только служебные события (номер, форма, каналы, длина текста).

Модалка (`ContactModal`): одна на сайт, открывается из шапки, hero, карточек форматов и шапки страницы оффера с темой; Esc закрывает, Tab ходит по кругу внутри окна, фокус уходит в первое поле, после закрытия возвращается на кнопку-открыватель, скролл блокируется; exit-анимация пружинная (~0.8 с), в автотестах ждать не меньше секунды. Встроенные формы — `LeadForm` на `/contacts` и `FooterForm` в футере остальных страниц.

Снятие ореола, поджатая маска, десатурация и боковое затемнение к hero больше не применяются; варианты с подъёмом сильнее (0/0.16, 0/0.22 с saturation 0.9–0.93) выглядели выцветшими. **«Обо мне» с 21.10.2026** — кадр `003.png` (водолазка, анфас; одна из первых вырезок с чёрного фона: 2,8% полупрозрачных пикселей, край почти чёрный) по тому же правилу: `victor-about.webp` — `cwebp -q 85 -alpha_q 95 -m 6 -sharp_yuv -resize 720 900` без фильтров (33 КБ); `victor-about-light.webp` — только снятие чёрной каймы края (`geq` делит RGB на `max(alpha, 48)`, непрозрачные пиксели не меняются) и тот же подъём теней `curves=all='0/0.10 0.2/0.27 0.5/0.54 1/1'`, `-alpha_q 100`, ресайз в cwebp (32 КБ). Проверка края — композит на `--box-deep` светлой `#ebeae7`. Конвейер ниже остаётся как описание прежних файлов и для вырезок, где край нужно чистить сильнее.

Портреты из прежних вырезок владельца (PNG с альфой 1122×1402) готовились без графического редактора — ffmpeg + cwebp, скрипт повторять по описанию: 1) снять чёрный ореол с полупрозрачного края волос — `geq` делит RGB на альфу (`min(255, r(X,Y)*255/max(alpha(X,Y),1))`), иначе на светлой панели край темнеет; 2) цветокоррекция на RGB без альфы (`alphaextract` → фильтры → `alphamerge`): `colortemperature=temperature=7400:mix=0.6` (убрать тёплый оттенок кожи), `huesaturation=saturation=-0.35`, `curves=all='0/0 0.12/0.06 0.5/0.49 0.9/0.93 1/1'` (тени в чёрный — рубашка сливается с `--bg`), `eq=contrast=1.06`; 3) имитация бокового света — `geq` гасит RGB линейно от 45% ширины к правому краю до −30%; 4) обрезка: hero с вечера 20.10.2026 (макет «Hero 1b», кадр 300.png) не обрезается — 1122×1402 целиком: на десктопе картинка масштабируется от высоты области (125%, верх −24px под шапку), а при узкой колонке 993–1200 её ограничивает ширина, и обрезанный снизу кадр показал бы ровный край; прежний hero из кадра анфас был обрезан до 1122×1262 (8:9); 5) `cwebp -q 82 -alpha_q 95 -m 6 -sharp_yuv [-resize W H]` — ресайз внутри cwebp, он премультиплицирует альфу (ffmpeg `scale` дал бы тёмную кайму); hero без ресайза (на 760px вывода это ~1.5×). Итог: hero 1122×1402 (60 КБ), финал и «Обо мне» 720×900 (30 КБ).

Светлая тема — отдельные файлы `*-light.webp` (вечер 20.10.2026, замечание владельца: на светлой панели у вырезки грязный край и фигура — чёрное пятно). Причина: вырезки сделаны с фото на чёрном фоне, полупрозрачная кромка (альфа 30–120) несёт в себе чёрный фон, а «тёмная» кривая давит тени в ноль. На тёмном фоне это невидимо, одной картинкой на обе темы не обойтись. Конвейер светлого варианта: 1) маска поджата — `alphaextract` → `geq=lum='clip((lum(X,Y)-77)*255/178,0,255)'` (альфа ниже 30% в ноль, остальное растянуто) → `gblur=sigma=0.5`; 2) RGB снимается с ореола тем же делением на альфу, но делитель `max(alpha, 48)`, чтобы не раздувать шум у края; 3) `colortemperature=7400:mix=0.6`, `huesaturation=saturation=-0.25`, `curves=all='0/0.07 0.1/0.15 0.5/0.5 0.9/0.9 1/1'` (чёрный поднят до ~#121212 — рубашка графитовая со складками, а не дыра), без `eq` и без бокового затемнения; 4) `alphamerge`; 5) `cwebp -q 82 -alpha_q 100 -m 6 -sharp_yuv [-resize W H]` — альфа без потерь, чтобы поджатый край не ступенился. Итог: hero-light 1122×1402 (47 КБ), about-light 720×900 (28 КБ).

- **Сервер.** Согласие и редакция проверяются сервером; `server/legal.json` хранит версию и SHA-256 текстов (сверка — `legal.test.ts`); запись о согласии — `consents.jsonl` в `StateDirectory` (без имени, контакта и текста); номер заявки в письме, уведомлении, ответе формы и записи; origin-проверка, лимит, ловушка, защита от повтора по `submissionId`. Почта — основной канал, Telegram — уведомление (`TELEGRAM_CONTENT`).
- **Cookie.** Уведомление внизу экрана при первом посещении (текст владельца от 22.10.2026): «Сайт сохраняет выбранную тему и настройки конфиденциальности на вашем устройстве, а также использует аналитические cookie. Подробнее — об использовании cookie и локального хранилища.» Одна кнопка «Понятно» (закрывает и пишет `privacy-notice` на 180 дней). Аналитические cookie упомянуты заранее: Яндекс Метрика подключится после добавления сайта в поисковики; в `/cookies` §3 и `/privacy` §2, §5 она описана с оговоркой «подключается после добавления в поисковые системы; до подключения данные не собираются / cookie не устанавливаются» — при подключении счётчика эти оговорки снять, перечислить cookie Метрики и сроки, поднять редакции. Окно «Настройки cookie» (три записи сайта с отметкой «есть на этом устройстве», строки про аналитику и рекламу, «Удалить сохранённые настройки», Esc/Tab/возврат фокуса) и кнопки к нему в уведомлении и футере скрыты флагом `COOKIE_SETTINGS_ENABLED = false` в `data/legal.ts` до появления настоящих необязательных категорий — код остаётся, в текстах документов кнопка не упоминается (тест). Хранилище недоступно → уведомление просто показывается снова, сайт работает.
- **Проверено 22.10.2026** (dev-сервер + обработчик с тестовым SMTP-приёмником и `CONSENT_LOG_DIR` в scratchpad, headless Chrome по CDP; production-сборка через `vite preview`): три документа при прямом открытии, refresh и переходах — один H1, title/description/canonical, оглавление и якоря с учётом шапки, без ошибок консоли; 375/1440, обе темы, таблицы строками на телефоне, `scrollWidth = innerWidth`; уведомление в чистой сессии, после «Понятно» и refresh не показывается, отметка — только версия и дата; окно настроек открывается из футера, показывает записи, удаляет их; форма футера на `/services/landing`: строка услуги, ссылка в чекбоксе не отмечает его и открывает документ в новой вкладке, пустая отправка — три ошибки и фокус в контакт, без согласия — ошибка и ни одного письма, с согласием — письмо в приёмник (номер, время, форма, тема, контакт, текст, страница, строка о согласии) и строка в `consents.jsonl` без персональных данных, номер показан посетителю; модалка из шапки без темы и из шапки услуги с темой — то же; `curl`: без согласия 400, чужая редакция 400, чужой Origin 403, 40 КБ 413, битый JSON 400, ловушка 200 без доставки, повтор `submissionId` — тот же номер и одно письмо, лимит 429; обработчик без SMTP → `ready: false` и 503, только Telegram-уведомление → `ready: false`. - **Как менять тексты.** Править `data/legal.ts`, поднять версию документа в `LEGAL_VERSIONS` (и `LEGAL_EFFECTIVE_DATE`), `npm run legal:hash` → `server/legal.json`, `npm test`. Новая редакция cookie-страницы показывает уведомление снова; новая редакция согласия заставляет старую сборку в браузере получать 400 до обновления страницы.
