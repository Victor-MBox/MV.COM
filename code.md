# MV.COM — документация проекта

Сайт-портфолио Виктора Мацакова (будущий домен victormatsakov.com). Одностраничное React-приложение с клиентским роутингом. Этот файл — опорная точка для дальнейшей работы: архитектура, контент, дизайн-система, соглашения и список незакрытых задач. Обновлять при каждом заметном изменении. Смысловая часть (кому продаём, какие тексты писать, аудит, план переработки) — в `content.md`; этапы 0–2 плана выполнены 19 октября 2026, этап 3 (реальный контент) за владельцем. Редизайн по `docs/design-spec.md` (дизайн-система 1.0) реализован на маршруте `/home3` 19.10.2026, приёмка и перенос внутренних страниц — за владельцем. Четвёртый вариант главной `/home4` (аналог https://portilo.framer.website/, навигация в верхней шапке вместо левого меню) реализован 19.10.2026 по `docs/design-spec-home4.md`; владелец сравнивает четыре варианта (`/`, `/home2`, `/home3`, `/home4`) и выбирает один.

```bash
npm ci              # зависимости по lock-файлу (Node 22)
npm run dev         # http://localhost:5173
npm run build       # dist/ (в .gitignore)
npm run preview     # http://localhost:4173, отдаёт dist/ с SPA-fallback
npm run type-check  # tsc --noEmit -p tsconfig.app.json
```

Перед тем как считать задачу готовой: `type-check`, `lint`, `test`, `build` зелёные. `type-check` обязан указывать на `tsconfig.app.json`: корневой `tsconfig.json` содержит только `references` и `files: []`, поэтому голый `tsc --noEmit` ничего не проверял (так было до 19.10.2026).

Третьего уровня `/services/:group/:service` больше нет: старые адреса отдают 404 (сайт не в продакшене, редиректы не нужны).

Правила:
- Внутренние ссылки только через `Link`/`NavLink`, внешние — `<a target="_blank" rel="noopener noreferrer">`.
- Активный пункт меню считается в `LeftMenu` по `pathname.startsWith(to)` (главная — `isHomeRoute` из `routes.ts`: `/`, `/home2`, `/home3`, `/home4`; на маршрутах `isV2Route` в меню монограмма, а не фото — §6.1 ТЗ). Пункт «Блог» из `MENU` убран. На `/home4` вместо `LeftMenu` рендерится `TopHeader` (`isTopHeaderRoute`), активная ссылка — по `startsWith`, «Главная» — логотип.
- `ScrollToTop`: если `getLenis()` вернул инстанс (страницы `/home3`, `/home4`), прокрутка наверх и к якорю идёт через `lenis.scrollTo`, иначе как раньше. Условий по маршруту в нём нет; отступ под липкую шапку `/home4` даёт `scroll-margin-top: var(--header-h)` секций — Lenis учитывает его сам (не передавать ещё и `offset`, иначе отступ удвоится).
- `ScrollToTop` прокручивает наверх при смене пути; если есть `#hash`, ждёт появления элемента (до ~1 с, потому что страница монтируется после exit-анимации AnimatePresence) и скроллит к нему. У секций-якорей стоит `scroll-margin-top`.
- Несуществующий `:slug`/`:offer` → компонент возвращает `<NotFoundPage />`.
- Хостинг должен отдавать `index.html` на любой путь (SPA fallback), иначе прямые ссылки на внутренние страницы дадут 404.

## 4. Контент как данные (`src/data`)

Весь текст, цены, ссылки и картинки живут здесь. Чтобы изменить контент, править эти файлы, а не компоненты. Правило контента: один факт — одно место на странице; числа только настоящие; технические термины на страницах для бизнеса — только внутри аккордеонов и блока «Для HR».

- `offers.ts` — **витрина услуг**: `OFFERS` (7 офферов из content.md §4.2). Поля: `key` (URL), `title`, `line` (строка на карточке и подзаголовок страницы), `forWhom` (три слова для /services), `priceFrom`, `priceDetail?`, `term`, `cta` («Обсудить лендинг» — подпись кнопки CTA-баннера, винительный падеж), `audience[3]`, `notFor[1–2]`, `outcomes[5–8]`, `priceFactors[3]`, `notIncluded[]`, `afterLaunch?` (иначе общий `AFTER_LAUNCH`), `faq[3–5]`, `services[]` (ключи из `SERVICES`), `categories[]` (связь с кейсами для блока «Примеры»; нет совпадений — блок скрыт), `tech { stack[], notes[] }` — единственное место с технологиями на странице. Хелперы `getOffer`, `offerPath`.
- `services.ts` — **справочник подуслуг**, не витрина: `SERVICE_GROUPS` (7 направлений: `key`, `title`, `short`) и `SERVICES` (32 подуслуги: `key`, `group`, `title`, `short`, `outcome`, `includes[]`, `priceFrom`, `term`, `stack[]`). Собственных страниц нет: подуслуги перечисляются внутри аккордеона «Как это устроено технически» на странице оффера. Каждая подуслуга входит хотя бы в один оффер (проверяется тестом). Хелперы `getGroup`, `getService`, `getServicesByGroup`. Тип `Faq` объявлен здесь.
- `pricing.ts` — `PRICING_MODELS` (три формата оплаты), `PRICING` (блок «Сколько стоит» из content.md §4.3: `included`, `factors`, `estimate`, `reading`, `supportExample`, `terms`, `notDoing`), `AFTER_LAUNCH`, `BUDGET_RANGES` (вилки бюджета в форме).
- `faq.ts` — единый `FAQ` (11 вопросов, content.md §4.9) с ключами; `HOME_FAQ_KEYS`, `CONTACTS_FAQ_KEYS`, `getFaq(keys)`. Ответ про договор и ИП закреплён тестом — менять только по решению владельца.
- `home.ts` — `AVAILABILITY` (статус «Беру проекты с ноября» — владелец от него отказался, показывается только на `/home2`), `PROOF` (два числа строки доказательства), `HR_LINE` (стек и город для третьей колонки), `HOME_OFFER_LAYOUT` (порядок плиток офферов на главной: `key`, `tone` синий/оранжевый, `wide`; тест проверяет, что покрыты все семь офферов), `WHY_ME` (4 обещания), `WHY_ME_PROOF`, `HR_BLOCK` (текст блока для HR и путь к резюме `/cv.pdf`).
- `home2.ts` — данные только для `/home2` (концепт H): `HERO_KICKER` (единственный ярлык в верхнем регистре на странице), `HERO_SUBTITLE` (короткий подзаголовок под портрет), `HERO_FACTS` (те же два факта, что в `PROOF`, но числом для счётчика), `AUDIENCES` (четыре таба «Кому я нужен»: `label`, `title`, `text`, `items[3–4]`, `cta` — тема формы или ссылка на резюме, `link`, `tone` синий/зелёный/оранжевый/нейтральный). Тест `home2.test.ts` следит, что темы кнопок совпадают с названиями офферов и что в текстах табов нет чисел из hero и цены агентств.
- `home3.ts` — данные только для `/home3` (дизайн-система 1.0, docs/design-spec.md §14). Новые строки помечены `// TODO (владелец)`: `MOTTO` (две строки девиза), `H2` (заголовки секций с одним акцентом: `{ text, accent }`), `FINAL_STATS` (четыре счётчика финала; значения привязаны к `EXPERIENCE`, `PROCESS`, `PRICING.estimate`, `AFTER_LAUNCH` тестом), `CTA_MARQUEE`, `INTENTS` и `JOB_FORMATS` (намерения формы), `FORM_COPY` (лид, успех, «что будет дальше»). Производные от существующих данных: `HERO_OFFER` (HERO_SUBTITLE, последняя фраза — акцентной строкой), `HERO_STATS` (три числа из `PROOF`, второй факт разбит на два), `FEATURED_OFFERS` / `ROW_OFFERS` (какие офферы — карточками, какие — строками). Хелпер `parseStat('18 000+') → { value: 18000, suffix: '+' }` используется и в `CaseCard`. Тест `home3.test.ts`.
- `projects.ts` — `PROJECTS`: сейчас один реальный кейс `norandoms` (`featured`). Поля: `tagline` (строка в шапке кейса), `line` (строка карточки, без чисел), `highlights[3]` (три факта широкой карточки), клиент/год/роль/срок, `stack`, `categories`, `link`, `cover`, `showcase[2]` (два скриншота для блока главного кейса на главной: большой сверху справа, малый снизу слева), `gallery`, `task`/`solution`/`result` (блок «Коротко», без повторения цифр), `metrics[4]` (единственное место с числами на странице кейса), `status`, `features[]`, `scheme[]`, `process[]` (рендерятся внутри аккордеона). `PROJECT_CATEGORIES` выводится автоматически; `getAdjacentProjects` возвращает `undefined`, если проект один. Цифры NoRandoms актуальны на октябрь 2026 — обновлять вручную.
- `posts.ts` — `POSTS` с контентом в виде блоков (`p | h2 | ul | quote | code`), `cover` необязателен (стоковых обложек нет), `formatDate`.
- `experience.ts` — `EXPERIENCE` (аккордеон опыта), `STACK_GROUPS` (стек группами для «Обо мне»), `PROCESS` (4 шага, единственный процесс на сайте, content.md §4.4).
- `contacts.ts` — `CONTACTS` и `CONTACT_LINKS` (единственное место с контактами: меню, соцкнопки, CTA-баннер, страница контактов, блок HR).

## 5. Дизайн-система

### Шрифт и темы
- Шрифты подключены в `index.html` (`preconnect` + `<link rel=stylesheet>`, с 19.10.2026 вместо `@import` в `_main.scss`): `Geologica` для заголовков через `--font-title` (правило `h1, h2, h3, .title` в `_main.scss`; у `span`-заголовков плиток `font-family` задаётся явно) и `Golos Text` для текста через `--font-body` (правило `*`). `Jura` убран 19.10.2026 вместе с переходом главной на концепт D. Третий шрифт `JetBrains Mono` (`--font-mono`, 400/500) — служебный слой дизайн-системы 1.0 (см. ниже). `letter-spacing`: текст −0.01em, заголовки −0.03em, H1 главной −0.04em.
- Глобальное правило `* { font-family: var(--font-body) }` задаёт шрифт каждому элементу явно, поэтому `span` внутри заголовка или кнопки не наследует Geologica/моно: в новых компонентах текстовым потомкам ставится `font-family: inherit` (в `HomePage3.scss` — общее правило для `h1–h3, .motto, .accent`).
- Темы: переменные объявлены в `_variables.scss` трижды — `:root` (тёмная по умолчанию), `body.light`, `body.dark`. Новую переменную добавлять во все три блока.
- Тёмная тема первична, светлая проверяется после каждого нового блока.

## 6. Адаптив

Файл `_responsive.scss`, точки 1200 / 992 / 768 / 560. **Все правила обёрнуты в `body { ... }`** — это намеренно: стили компонентов попадают в бандл после глобальных, и без повышения специфичности переопределения проигрывают. Новые адаптивные правила добавлять внутрь таких же обёрток.

## 7. Соглашения по коду

- Табы, одинарные кавычки, без точек с запятой, JSX-атрибуты в одинарных кавычках — как в исходном проекте.
- Типы импортировать через `import type` (требование `verbatimModuleSyntax`). Без `enum` и параметров-свойств конструктора.
- Файл с компонентом экспортирует только компоненты (правило `react-refresh/only-export-components`): хуки и контексты — в отдельные `.ts` (пример: `ContactModalContext.ts` + `ContactModalProvider.tsx`).
- Нельзя вызывать `setState` синхронно в `useEffect` (`react-hooks/set-state-in-effect`). Для сброса формы по новому пропу используется `key` (см. `ContactModal`).
- SVG-атрибуты в JSX в camelCase (`strokeWidth`, `clipPath`).
- Декоративные SVG — `aria-hidden='true'`, у интерактивных элементов есть `aria-label`.
- Картинки вне первого экрана — `loading='lazy'`.
- Анимации: framer-motion для появления/переходов (`whileInView` + `viewport={{ once: true }}`), gsap для числовых. `App` обёрнут в `<MotionConfig reducedMotion='user'>`, плюс глобальное CSS-правило `prefers-reduced-motion`. Ховер-подъём карточек, которые анимирует framer-motion, делать через `whileHover`, а не CSS `transform` — инлайновый transform от framer перебьёт CSS.
- Контактные данные и ссылки — только из `data/contacts.ts`.
- `.container` — флекс-элемент с `min-width: 0`: иначе любой блок с большим min-content (бегущая строка `width: max-content`, длинное слово) раздувает страницу и даёт горизонтальный скролл. Бегущим строкам дополнительно ставить `contain: inline-size` на обёртку с `overflow: hidden`.
- `CountUp` рендерит `<span>`: внутри `<strong>` с числом задавать `strong span { font: inherit; color: inherit }`, а подписи выбирать через `> span`, иначе число получает стиль подписи (мелкий размер и шрифт текста).
- Контейнерные запросы: `@container` смотрит на ближайшего *предка* с `container-type`, а не на сам элемент — поэтому контейнер для `MiniUi` объявлен на `.offerBox`, а `cqi` девиза считается от `.home3`. Элементы с `position: fixed` внутри контейнера привязываются к нему (`contain: layout`), поэтому `Cursor` и модалка рендерятся порталом в `body`.
- Правило `react-hooks/set-state-in-effect`: измерения с `setState` делать в асинхронных колбэках (`document.fonts.ready.then`, `ResizeObserver`, `setInterval`), как в `SplitLines` и `useClock`; подписки на `matchMedia` — через `useSyncExternalStore` (`useMediaQuery`).
- Lenis поднимается только страницей, которой он нужен (`useLenis()`), и уничтожается при размонтировании; пока открыта модалка или мобильное меню `/home4` — `lenis.stop()`. `lenis.scrollTo(element)` сам вычитает `scroll-margin-top` элемента.
- `backdrop-filter` на элементе делает его containing block для `position: fixed` потомков — у `TopHeader` фон и блюр лежат на `::before`, а панель меню и соцпанель рендерятся порталом в `body`.
- У `motion.div` пропы `onDragStart` / `onDragEnd` — колбэки жеста framer-motion, а не нативные события `dragstart`; нативный DnD ссылок и картинок внутри drag-ленты гасится через `addEventListener('dragstart', preventDefault)` (см. `WorkSlider`).
- Правило `:is(h1, h2, h3) * { font-weight: inherit }` в скоупе страницы тянет UA-bold заголовков в потомков (`.dimAcc__title` внутри `h3.dimAcc__head`): в `HomePage4.scss` заголовкам явно задан вес 500, а наследование включено только для h1/h2 и выделений. В `HomePage3.scss` такое правило есть с `h3` — см. бэклог.
- Вложенный селектор `&__theme` внутри медиазапроса компилируется в `.topHeader__theme` той же специфичности, что и базовое правило ниже по файлу, и проигрывает ему; для переопределений в медиазапросах добавлять родителя (`&__actions &__theme`).
- Списки внутри `Accordion` сбрасывать от стилей `.accordion__body ul` (маркеры, отступ) через селектор с двумя классами, как в `ProjectPage.scss` и `OfferPage.scss`.

## 8. Форма и модалка

`ContactForm` валидирует имя, контакт (e-mail / телефон / @ник), сообщение и согласие, показывает ошибки по полям, состояние отправки и экран успеха. Поля «Что нужно сделать» (7 офферов + «Другое») и необязательное «Бюджет» (вилки из `BUDGET_RANGES`) стоят в одном ряду. Если `open(topic)` передал значение не из списка офферов, оно добавляется отдельной опцией. Отправка идёт через `submitContact` в `src/api/contact.ts` — сейчас это имитация с задержкой 900 мс и `console.info` в dev. Для боевого режима заменить тело функции на `fetch` к своему endpoint или сервису форм; интерфейс `ContactPayload` (`name`, `contact`, `topic`, `budget?`, `message`) не менять.

Esc закрывает модалку; exit-анимация диалога пружинная (~0.8 с), в автотестах ждать не меньше секунды.

На `/home3` модалка рендерит `LeadForm` (намерения «Проект / Вакансия или контракт / Вопрос», см. §5), на остальных страницах — прежний `ContactForm`. Правила валидации у обеих форм общие: `components/contactForm/validate.ts`.

В сессии 19.10.2026 всё это делалось тремя скриптами на Chrome DevTools Protocol (headless Chrome `/Applications/Google Chrome.app` + Node 22 `WebSocket`, без зависимостей): `shoot.mjs` — скриншоты всех страниц в двух темах и на 390px с проверкой `scrollWidth`; `interact.mjs` — модалка, форма, 404, блог, тема, якорь `#faq`; `audit.mjs` — повторы чисел, uppercase-ярлыки, запрещённые фразы, число светлых кнопок на первом экране; `clip.mjs` — скриншоты заданных участков страницы (`Page.captureScreenshot` с `clip` и `captureBeyondViewport`), потому что `sips --cropOffset` режет не там. Скрипты в репозиторий не входят (живут в scratchpad сессии), при необходимости пишутся заново по этому описанию: `/json/new` → `Page.navigate` → `Runtime.evaluate` → `Page.captureScreenshot` с `captureBeyondViewport`.

Для `/home4` (19.10.2026) скрипты написаны заново на общем клиенте `cdp.mjs` (порт и профиль из `CDP_PORT`, чтобы запускать параллельно): `shoot.mjs` — полные страницы в двух темах с проверкой `scrollWidth`; `clip.mjs` — посекционные кадры: вьюпорт ставится в высоту секции и кадр берётся без `captureBeyondViewport`, потому что полностраничный захват рисует липкую шапку не на месте и растягивает hero с `100svh` (после смены высоты вьюпорта секцию нужно мерить заново); `header.mjs` — шапка после прокрутки и открытое мобильное меню; `interact.mjs` / `mobile.mjs` — ховер и фокус витрины, курсор-подпись, модалка, тема, Tab по кольцу меню и Esc, тап по витрине через `Input.dispatchTouchEvent` (вьюпорт 390, `mobile: true`), `prefers-reduced-motion` через `Emulation.setEmulatedMedia`, интро один раз за сессию, якорь `#faq`; `slider.mjs` / `drag.mjs` — слайдер с временно добавленным вторым проектом (стрелки, ромбы, прогресс, свайп мышью через `Input.dispatchMouseEvent` с `buttons: 1`); `audit.mjs` — элементы в верхнем регистре, веса > 500, акцентные элементы и повторы чисел по `innerText` после прокрутки (счётчики до прокрутки показывают 0). Якорь с `#hash` на тот же документ не даёт `Page.loadEventFired` — переходить через `about:blank`.

Для `/home3` (19.10.2026) те же три скрипта переписаны: `shoot.mjs --paths /home3 --widths 1440,1024,390 --themes dark,light` (тема через `localStorage.theme` + перезагрузка, прокрутка вниз и вверх шагами по 60% экрана с паузами, затем 2,6 с на счётчики — иначе числа ловятся на середине анимации), `clip.mjs --y --h [--hover sel] [--eval js]` для участков и отладки (так нашли переполнение на 390 и застрявшее состояние `splitLines--measuring`), `interact.mjs` — ховеры через `Input.dispatchMouseEvent`, клики, Esc, `Emulation.setEmulatedMedia` с `prefers-reduced-motion: reduce`, вьюпорт 390 с `mobile: true`. При эмуляции `mobile: true` переполнение видно по `innerWidth` > ширины устройства, а не только по `scrollWidth`.

## 10. Принятые решения

- Две аудитории (бизнес и HR) на одном сайте: бизнес-язык по умолчанию, техника на уровень глубже — аккордеон «Как это устроено технически» на кейсе и оффере, блок «Для HR и тимлидов» на главной, страница «Обо мне» как страница для найма.
- Витрина услуг — 7 офферов (`offers.ts`), два уровня `/services` → `/services/:offer`. 32 старые услуги остались справочником подуслуг и источником для аккордеона. 1С-Битрикс — не направление, а одна строка внутри оффера «Поддержка и доработка сайта».
- Один процесс работы на сайт (`PROCESS`, `ProcessList`): на главной, /services и страницах офферов. На «Обо мне» процесса нет.
- Счётчики `NumbersCard` удалены; вместо них строка доказательства под hero с двумя фактами (8 лет; NoRandoms 6 000+ пользователей и 500+ посетителей в день). Третьего числа нет, потому что реального числа проектов нет.
