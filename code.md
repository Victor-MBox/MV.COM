# MV.COM — документация проекта

Сайт-портфолио Виктора Мацакова (будущий домен victormatsakov.com). Одностраничное React-приложение с клиентским роутингом. Этот файл — опорная точка для дальнейшей работы: архитектура, контент, дизайн-система, соглашения и список незакрытых задач. Обновлять при каждом заметном изменении. Смысловая часть (кому продаём, какие тексты писать, план) — в `content.md`.

Дополнение 21.10.2026 (второе ТЗ владельца «доработать содержание и услуги»): иллюстрации услуг в карточках каталога и на главной (сцена при появлении и по ховеру/фокусу), «Техническое обслуживание» от 3 000 ₽ вместо «сопровождения от 25 000 ₽» и пакеты обслуживания на `/services/support#packages`, ответ «Работаете по договору?» владельца, фраза о 20+ проектах на «Обо мне», форма до готовности обработчика и политики в публичной сборке заменена кнопкой «Написать в Telegram» (на dev — тестовый режим с меткой). Первый экран, блок проектов, `/portfolio` и кейсы не менялись.

Состояние на 21.10.2026: содержание и коммерческая структура переделаны по ТЗ владельца «содержание и коммерческая структура сайта» (см. §10, запись от 21.10.2026): главная — предложение в H1 → реальные проекты → шесть услуг карточками → процесс → стоимость и условия → кратко о разработчике → пять вопросов → футер-форма; единая форма первого обращения из трёх полей; блок «Для HR», бегущие строки, счётчики и витрина-переключатель с главной убраны (компоненты удалены, последний коммит с ними `e26f1ac`).

## 4. Контент как данные (`src/data`)

Весь текст, цены, ссылки и картинки живут здесь. Чтобы изменить контент, править эти файлы, а не компоненты. Правило контента: один факт — одно место на странице; числа только настоящие; технические термины на страницах для бизнеса — только внутри аккордеонов и блока «Для HR». Строки, которые владелец должен утвердить, помечены `// TODO (владелец)`.

- `offers.ts` — **каталог услуг**: `OFFERS` (7 офферов; порядок массива = порядок карточек и номер «услуга 0N»: сайт компании, лендинг, магазин, кабинет/веб-сервис, интеграции, доработка, агентства), `CATALOG` (шесть без агентств — главная и `/services`), `AGENCIES_KEY` (агентства — строкой под сеткой). Поля: `key` (URL), `title`, `line` (описание на карточке и лид страницы услуги — тексты ТЗ от 21.10.2026), `forWhom` (не выводится), `priceFrom`, `priceDetail?`, `prices?` (строки «подпись — цена»: на карточке подпись над ценой, на странице услуги — по бейджу; первая равна `priceFrom` — тест; у кабинета/веб-сервиса «Личный кабинет — от 150 000 ₽» и «Первая версия продукта — от 300 000 ₽», у доработки «Разовая задача — от 15 000 ₽»), `term`, `hideTermOnCard?` (доработка), `cta` («Обсудить лендинг» / «Обсудить задачу»), `process?` (свои четыре шага у интеграций, доработки и агентств), `audience[3]`, `notFor[1–2]`, `outcomes[5–8]`, `priceFactors[3]`, `notIncluded[]`, `afterLaunch?` (иначе `AFTER_LAUNCH`), `faq[3–5]`, `services[]`, `categories[]`, `tech { stack[], notes[] }`. Хелперы `getOffer`, `offerPath`.
- `services.ts` — **справочник подуслуг**, не витрина: `SERVICE_GROUPS` и `SERVICES` (32 подуслуги); собственных страниц нет — перечисляются в аккордеоне «Стек и детали» страницы оффера. Каждая входит хотя бы в один оффер (тест). Тип `Faq` объявлен здесь.
- `pricing.ts` — `SUPPORT_PACKAGES` (пакеты обслуживания 3 000 / 10 000 / 24 000 ₽ в месяц — проект условий, владелец проверяет перед публикацией; без сроков реакции и графика), `SUPPORT_TERMS` (пять условий), `PACKAGES_OFFER` / `PACKAGES_ANCHOR` / `PACKAGES_PATH` (`/services/support#packages`); `PRICING_MODELS: PricingModel[]` (три формата: «Проект по смете», «Доработки» 3 500 ₽ / час, «Техническое обслуживание» от 3 000 ₽ / месяц — цена из младшего пакета; у каждого `cta`, у третьего `to` — кнопка-ссылка «Посмотреть пакеты» вместо модалки), `PRICING` (`agree`, `factors`, `reading`, `notDoing`), `AFTER_LAUNCH`. Удалены 21.10.2026: `included`, `estimate`, `terms`, `BUDGET_RANGES`, `supportExample` («8 часов × 3 500 ₽» противоречил пакетам), «сопровождение от 25 000 ₽».

## 7. Соглашения по коду

- Табы, одинарные кавычки, без точек с запятой, JSX-атрибуты в одинарных кавычках.
- Типы импортировать через `import type` (`verbatimModuleSyntax`). Без `enum` и параметров-свойств конструктора.
- Файл с компонентом экспортирует только компоненты (`react-refresh/only-export-components`): хуки и контексты — в отдельные `.ts` (`ContactModalContext.ts` + `ContactModalProvider.tsx`).
- Нельзя вызывать `setState` синхронно в `useEffect` (`react-hooks/set-state-in-effect`): измерения — в `document.fonts.ready.then` / `ResizeObserver` (как `SplitLines`), подписки — через `useSyncExternalStore` (`useMediaQuery`, `useTheme`); сброс формы по новому пропу — через `key`.
- SVG-атрибуты в JSX в camelCase; декоративные SVG — `aria-hidden='true'`; у интерактивных элементов `aria-label`; картинки вне первого экрана — `loading='lazy'`.
- Анимации: framer-motion для появления и переходов (`App` в `<MotionConfig reducedMotion='user'>` + глобальное правило `prefers-reduced-motion`), gsap для чисел. Ховер-подъём карточек, которые анимирует framer, — через `whileHover`, не CSS `transform`.
- Контактные данные и ссылки — только из `data/contacts.ts`; тексты — из `data/*`, в страницах остаются только строки, относящиеся к одной странице (ABOUT, PRINCIPLES, CHANNELS, H1 и H2 с `TODO (владелец)`).
- Новые страницы: `PageHead` → секции `.section > .container` с `SectionHead`; финальный призыв с формой даёт общий футер, своего CTA-блока у страниц нет; только токены 1.0 и компоненты §5; старых классов (`.btn`, `.card`, `.titlerow`) и токенов (`--bg-primary`, `--accent-blue`) в проекте нет — не возвращать.
- Тема: `useTheme` — единый стор (`useSyncExternalStore`); `localStorage.theme` пишется только при ручном выборе; тот же алгоритм продублирован инлайн-скриптом в `index.html` — при изменении ключа или правил менять оба места.
- Lenis поднимает только главная (`useLenis()`); пока открыта модалка или мобильное меню — `lenis.stop()`; `lenis.scrollTo(element)` сам вычитает `scroll-margin-top`.
- Прокрутку под оверлеем блокирует только `useScrollLock(active)` (модалка, мобильное меню, лайтбокс), не `body.style.overflow`: `overflow: hidden` на `html` (на `body` он делает body контейнером прокрутки — липкая шапка на прокрученной странице уезжает вверх), ширина пропавшей классической полосы прокрутки уходит в `--scrollbar-gap` → `padding-right` у `body` и `right` у `.socialDock` (новым `fixed`-элементам у правого края — так же). Оверлеи с центрированным содержимым — `left: 0; width: 100vw` вместо `inset: 0`: блокировка снимается сразу по закрытию, полоса возвращается во время exit-анимации, и с `right: 0` содержимое съезжало бы. Правила `.lenis-stopped { overflow }` в `_system.scss` нет намеренно — оно прятало полосу без компенсации.
- `backdrop-filter` делает элемент containing block для `position: fixed` потомков — у `TopHeader` фон и блюр на `::before`, панель меню, соцпанель, модалка, курсор и лайтбокс рендерятся порталом в `body`.
- У `motion.div` пропы `onDragStart`/`onDragEnd` — колбэки жеста; нативный DnD ссылок и картинок внутри drag-ленты гасится через `addEventListener('dragstart', preventDefault)` (так было в `WorkSlider`, удалён 21.10.2026).
- `useScroll({ target })` требует смонтированного `target` и не-static контейнера: у `CaseCard` опции передаются только при `wide`, `html { position: relative }` в `_system.scss`.
- Вложенный селектор `&__x` внутри медиазапроса компилируется в ту же специфичность, что и базовое правило ниже по файлу, — для переопределений в медиазапросах добавлять родителя (`&__actions &__theme`).
- Правило `:is(h1, h2, …) * { font-weight: inherit }` не включает h3/h4: иначе UA-bold утекал бы в `.dimAcc__title` внутри `h3.dimAcc__head`; заголовкам явно задан вес 500.

## 8. Форма и модалка

С 21.10.2026 форма первого обращения одна по составу и правилам на всех поверхностях (модалка, `/contacts`, футер): поля `LEAD_FIELDS` — «Как к вам обращаться» (необязательно), «Telegram или почта», «Что нужно сделать» — и обязательное согласие. Правила `validateContact` (`components/leadForm/validate.ts`, тест `leadForm.validation.test.ts`): контакт — почта, @ник или номер, иначе «Укажите Telegram или почту, чтобы я мог ответить»; пустая задача — «Коротко опишите, что нужно сделать»; без согласия — «Нужно согласие на обработку данных». Состояние, снятие ошибок по мере правки и отправка — хук `useLeadForm(topic)`; разметка своя у `LeadForm` (поля-карточки) и `FooterForm` (строки макета). `ContactPayload` = `{ name, contact, message, topic }`: `topic` — контекст, который ставит сайт (название оффера на его странице, формат из блока цен), в текст посетителя он не попадает; намерений, услуги и бюджета больше нет.

Готовность (`data/leadForm.ts`): пока нет обработчика доставки (`FORM_DELIVERY_READY`) и политики (`PRIVACY_POLICY_URL`), в публичной сборке формы нет — `LeadForm` и `FooterForm` рендерят `FormFallback` («Написать в Telegram», почта), вступление `/contacts` — без упоминания формы. На dev-сервере (`FORM_TEST_MODE`) форма видна с меткой тестового режима. Отправка — `submitContact` в `src/api/contact.ts`: в тестовом режиме имитация (900 мс, `console.info` с payload), сбой — `localStorage.setItem('contact-mock', 'fail')` (форма показывает «Не удалось отправить сообщение…» и сохраняет введённое); без обработчика — исключение. Успех без подтверждения сервера не показывается. Боевой режим: `fetch` к своему endpoint с проверкой `res.ok` в `submitContact`, затем `FORM_DELIVERY_READY = true` и `PRIVACY_POLICY_URL`; серверную проверку и защиту от спама держит обработчик; интерфейс `ContactPayload` сохранить.

Модалка (`ContactModal`): одна на сайт, открывается из шапки, hero, карточек форматов и шапки страницы оффера с темой; Esc закрывает, Tab ходит по кругу внутри окна, фокус уходит в первое поле, после закрытия возвращается на кнопку-открыватель, скролл блокируется; exit-анимация пружинная (~0.8 с), в автотестах ждать не меньше секунды. Встроенные формы — `LeadForm` на `/contacts` и `FooterForm` в футере остальных страниц.

Снятие ореола, поджатая маска, десатурация и боковое затемнение к hero больше не применяются; варианты с подъёмом сильнее (0/0.16, 0/0.22 с saturation 0.9–0.93) выглядели выцветшими. **«Обо мне» с 21.10.2026** — кадр `003.png` (водолазка, анфас; одна из первых вырезок с чёрного фона: 2,8% полупрозрачных пикселей, край почти чёрный) по тому же правилу: `victor-about.webp` — `cwebp -q 85 -alpha_q 95 -m 6 -sharp_yuv -resize 720 900` без фильтров (33 КБ); `victor-about-light.webp` — только снятие чёрной каймы края (`geq` делит RGB на `max(alpha, 48)`, непрозрачные пиксели не меняются) и тот же подъём теней `curves=all='0/0.10 0.2/0.27 0.5/0.54 1/1'`, `-alpha_q 100`, ресайз в cwebp (32 КБ). Проверка края — композит на `--box-deep` светлой `#ebeae7`. Конвейер ниже остаётся как описание прежних файлов и для вырезок, где край нужно чистить сильнее.

Портреты из прежних вырезок владельца (PNG с альфой 1122×1402) готовились без графического редактора — ffmpeg + cwebp, скрипт повторять по описанию: 1) снять чёрный ореол с полупрозрачного края волос — `geq` делит RGB на альфу (`min(255, r(X,Y)*255/max(alpha(X,Y),1))`), иначе на светлой панели край темнеет; 2) цветокоррекция на RGB без альфы (`alphaextract` → фильтры → `alphamerge`): `colortemperature=temperature=7400:mix=0.6` (убрать тёплый оттенок кожи), `huesaturation=saturation=-0.35`, `curves=all='0/0 0.12/0.06 0.5/0.49 0.9/0.93 1/1'` (тени в чёрный — рубашка сливается с `--bg`), `eq=contrast=1.06`; 3) имитация бокового света — `geq` гасит RGB линейно от 45% ширины к правому краю до −30%; 4) обрезка: hero с вечера 20.10.2026 (макет «Hero 1b», кадр 300.png) не обрезается — 1122×1402 целиком: на десктопе картинка масштабируется от высоты области (125%, верх −24px под шапку), а при узкой колонке 993–1200 её ограничивает ширина, и обрезанный снизу кадр показал бы ровный край; прежний hero из кадра анфас был обрезан до 1122×1262 (8:9); 5) `cwebp -q 82 -alpha_q 95 -m 6 -sharp_yuv [-resize W H]` — ресайз внутри cwebp, он премультиплицирует альфу (ffmpeg `scale` дал бы тёмную кайму); hero без ресайза (на 760px вывода это ~1.5×). Итог: hero 1122×1402 (60 КБ), финал и «Обо мне» 720×900 (30 КБ).

Светлая тема — отдельные файлы `*-light.webp` (вечер 20.10.2026, замечание владельца: на светлой панели у вырезки грязный край и фигура — чёрное пятно). Причина: вырезки сделаны с фото на чёрном фоне, полупрозрачная кромка (альфа 30–120) несёт в себе чёрный фон, а «тёмная» кривая давит тени в ноль. На тёмном фоне это невидимо, одной картинкой на обе темы не обойтись. Конвейер светлого варианта: 1) маска поджата — `alphaextract` → `geq=lum='clip((lum(X,Y)-77)*255/178,0,255)'` (альфа ниже 30% в ноль, остальное растянуто) → `gblur=sigma=0.5`; 2) RGB снимается с ореола тем же делением на альфу, но делитель `max(alpha, 48)`, чтобы не раздувать шум у края; 3) `colortemperature=7400:mix=0.6`, `huesaturation=saturation=-0.25`, `curves=all='0/0.07 0.1/0.15 0.5/0.5 0.9/0.9 1/1'` (чёрный поднят до ~#121212 — рубашка графитовая со складками, а не дыра), без `eq` и без бокового затемнения; 4) `alphamerge`; 5) `cwebp -q 82 -alpha_q 100 -m 6 -sharp_yuv [-resize W H]` — альфа без потерь, чтобы поджатый край не ступенился. Итог: hero-light 1122×1402 (47 КБ), about-light 720×900 (28 КБ).

21.10.2026 добавились `audit.mjs` (все 13 маршрутов на 375 / 768 / 1440, с `--reduced` — при reduced-motion: `scrollWidth`, ровно один H1, ссылки на `#` и неизвестные маршруты, вложенные интерактивные элементы, консоль) и `interact.mjs` (модалка с клавиатуры: Enter — `keyDown` с `text: '\r'`, иначе кнопка не нажимается; Tab по кругу, ошибки пустой формы, успех и payload в `console.info`, Esc и возврат фокуса; «Посмотреть проекты»; форма футера с темой оффера); прод-сборку с ошибкой отправки проверять через `vite preview`. Для полностраничного кадра высоту вьюпорта брать с запасом ~12%: `Reveal` срабатывает с отступом −10% снизу, и нижние блоки иначе остаются прозрачными.

Скриншоты и проверки в сессиях 19–20.10.2026 делались скриптами на Chrome DevTools Protocol (headless Chrome `/Applications/Google Chrome.app` с `--remote-debugging-port=9222` + Node 22 `WebSocket`, без зависимостей; скрипты живут в scratchpad сессии и пишутся заново по этому описанию): `cdp.mjs` — клиент (`/json/new` → `Page.navigate` → `Runtime.evaluate` → `Page.captureScreenshot`, сбор ошибок консоли); `clip.mjs --path --sel --width --theme --h --eval --click --full` — кадр секции: страница загружается при 900px, секция измеряется, затем страница перезагружается во вьюпорте высоты секции, прокручивается до неё и снимается вьюпорт (ресайз вьюпорта после загрузки даёт чёрный кадр, а `captureBeyondViewport` рисует липкую шапку не на месте); `overflow.mjs` — обход всех маршрутов на 390 с проверкой `scrollWidth === innerWidth` и консоли; `drag.mjs` — свайп слайдера мышью (`mousePressed` → шаги `mouseMoved` с `buttons: 1` → `mouseReleased`). Параллельные запуски делят профиль Chrome: тему надёжнее ставить через `--eval "document.body.classList.add('light')"`, кадры снимать последовательно. Якорь с `#hash` на тот же документ не даёт `Page.loadEventFired` — переходить через `about:blank`.

## 10. Принятые решения

- Две аудитории (бизнес и HR) на одном сайте: бизнес-язык по умолчанию, техника на уровень глубже — аккордеоны «Как это устроено технически» / «Стек и детали», «Обо мне» как страница для найма с секцией «Для команд и работодателей» (с 21.10.2026 на главной блока для HR нет).
