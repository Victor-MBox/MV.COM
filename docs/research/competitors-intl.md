# Бенчмарк: международные сайты фриланс-fullstack-разработчиков и студий 1–3 человек, которые продают услуги

Дата проверки: 19 октября 2026. Все сайты ниже открыты и прочитаны (главная + ключевые подстраницы: услуги, цены, кейсы, процесс, «о себе»). Цитаты приведены дословно на английском, рядом — перевод.

Контекст: victormatsakov.com (RU, React / TypeScript / Node / Laravel / PHP / MySQL) должен продавать двум аудиториям сразу — (1) владелец малого/среднего бизнеса, который заказывает сайт / магазин / веб-приложение / интеграцию / поддержку; (2) HR / техлид, который оценивает разработчика как найм.

---

## 0. Метод и выборка

**Поиск.** ~20 запросов (WebSearch, режим extended), среди них: «freelance full stack developer website services pricing packages», «best freelance web developer portfolio sites 2025 2026», «studio of one web developer pricing», «laravel react freelance developer hire me site», «productized web development services solo developer», «website in 7 days fixed price solo developer», «freelance laravel developer work with me case studies», «for recruiters freelance web developer portfolio», «freelance laravel vue react developer personal website pricing testimonials». Поисковая выдача по таким запросам почти целиком забита биржами (Upwork, Fiverr, Toptal) и агентскими «cost guides», поэтому бо́льшая часть сильных примеров найдена через вторичные ссылки и прямые проверки доменов.

**Открыто ~30 сайтов.** В основной бенчмарк вошли 8, ещё 4 — как вспомогательные/анти-примеры. Отсеяны: сайты, которые не продают услуги (большинство «известных имён» — см. раздел 3), агентства 20+ человек, шаблонные SEO-дорвеи, мёртвые/закрытые сайты, сайты с ошибками (juststeveking.uk — 403; dennissnellenberg.com — просроченный сертификат; matuzo.at — 500).

**Главный вывод до деталей.** Ни один из проверенных сайтов не решает задачу «две аудитории» целиком. Сайты, которые продают услуги (havis.dev, vayle.art, ryangittings.co.uk, rob-saunders.co.uk), почти полностью игнорируют HR: нет стека, нет резюме, нет таймлайна опыта. Сайты известных разработчиков (Chiang, Comeau, Robinson, Tompkins, Coursey, Freiberg, Dayan) — наоборот, не продают ничего. Ближе всех к обеим аудиториям: andrejgajdos.com (табы Skills / Experience / Code Samples + страницы услуг), vincentschmalbach.com (блоки «Background» и «Core stack» рядом с «Ways to work with me») и alexhooley.com (сегментация «какой разработчик вам нужен» + список стека). Это ниша, которую victormatsakov.com может занять осознанно.

Ещё одно наблюдение: **никто не прячет технические детали в аккордеон/тогл.** Сайты, ориентированные на бизнес, либо вообще не пишут стек в клиентских кейсах (havis, gittings, rob-saunders), либо выносят его в отдельную подписанную строку/секцию («Tech:», «How it was built», «DEVELOPMENT TOOLS») — так бизнес-читатель пропускает её глазами, а техлид находит за секунду.

- «Good fit / not a fit» — фильтр нецелевых, который одновременно повышает доверие.
- Таблица Before/After в кейсе — читается за 10 секунд.
- Фразы: «One developer. Direct line. No agency layers.» (Один разработчик. Прямая связь. Без агентских прослоек.), «You get me. Not a project manager.» (Вы получаете меня, а не проджект-менеджера.), «No surprises. Just work.», «Principles, not platitudes.», «The quote you get is the price you pay.» (Какую цену назвал — такую и заплатите.)

- Подзаголовок hero слишком нишевый (экзамены/сертификация) — случайный владелец кафе не поймёт, что это и про него.

- Прайс-лист доп. опций с ценами — клиент сам собирает смету, не задавая вопросов.
- Снятие трения: «no call», ответ в тот же день, «honest reason».
- Секция болей «Five things you were told last time» — говорит о прошлом негативном опыте клиента, а не о себе.
- «When it breaks, somebody picks up» (Если сломается — кто-то возьмёт трубку) — уход продаётся через страх, а не через список фич.

**Что плохо.**
- Нулевое социальное доказательство: ни одного отзыва, ни логотипа.
- Hero говорит «From 900 €», а пакет стоит 810 € — разночтение в первом же экране.
- Нет страниц кейсов и метрик (кроме одной), нет стека и About — HR-аудитории делать нечего.
- Слишком много побочных подписок (SMM, Voice AI на входящие звонки) размывают фокус «я делаю сайты».
- «Launch offer until 30.11.2026» — промо-дедлайны выглядят как у инфобизнеса.

## 5. Топ-5 приёмов и формулировок, которые стоит взять

1. **Hero = результат + срок/условие, а не «я разработчик».**
   «Your website live in 7 days. Price fixed before we start.» (vayle) — Сайт в сети через 7 дней, цена зафиксирована до старта. «I build the system your organisation actually needs, and nothing it doesn't.» (havis) — Строю систему, которая вам действительно нужна, и ничего лишнего. «I build, rescue, and scale SaaS… and complex web apps» (schmalbach) — три глагола покрывают три типа клиентов. «A website that turns visitors into enquiries.» (havis) — Сайт, который превращает посетителей в заявки. Для HR-слоя — вторая строка формата Wieruch: «React, Next.js, TypeScript, Node.js | Berlin | Available Remotely».

2. **Лестница фиксированных тарифов с ценой, сроком и составом + подписка на уход после.**
   havis: £1,200 (1 нед.) → £2,750 (2–3 нед.) → £4,500 (3–4 нед.) → «from £7,500» (4–8 нед.), затем «Care — Site £95/mo», «Change work £300 for 4 hours». vayle: 810 / 1.260 / 2.250 € с 7/14/21 рабочими днями, прайс доп. опций (язык 175 €, блог 250 €, бронирование 350 €), «Always included», «What is not included». Альтернатива для тех, кто не хочет фиксировать: честные диапазоны с факторами цены (gittings: «There are no packages… guides, not fixed prices») или вилки бюджета с примерами в форме (gajdos: «$5,000 to $10,000: static website, dashboard, or small integration»). Дешёвый входной продукт, который зачитывается в большой заказ (havis: аудит £750 «credited in full against a build commissioned within 90 days»).

3. **Карточка кейса = одна строка про результат; страница кейса = Problem → Before/After → Approach → Results → «Want a similar result?».**
   Карточки: «We helped grow a 6 figure a year revenue business to an 8 figure a year business» (set.studio), «50% lower bounce, 3× faster», «replaced 4 spreadsheets, about 200 users» (havis). Страница: таблица «Before and After» (havis: «~5 seconds → Under 2 seconds», «~70% → ~35%»), затем отзыв клиента и CTA «Want a similar result for your business? Free 20-minute discovery call. Fixed price and timeline before anything is signed.» Стек — отдельной подписанной строкой «Tech:» / «How it was built» (schmalbach, gajdos), а не внутри текста; в аккордеон никто не прячет — достаточно визуального отделения. Для живых проектов: «Work you can open right now — Every link opens the real site, not a mockup.» (vayle) и «Find on Google» (rob-saunders).

4. **Маршрутизатор по типу потребности в первом экране — так одна страница обслуживает обе аудитории.**
   «What kind of Next.js developer do you need?» → «One-off project developer / On-going development / Vibe-coded project rescue» с разным форматом цены (hooley). «Ways to work with me»: Fixed-price project / Flat rate / Hourly or retainer (schmalbach). «Start with what you need» (rob-saunders). «Good fit if you / Probably not a fit if you» (havis). Для HR — отдельный таб/вход «Skills / Experience / Code Samples» (gajdos) и «View Full Résumé» (chiang), не смешанный с клиентскими блоками.

5. **Снятие риска и трения конкретными обещаниями вместо прилагательных.**
   «Get a Quote in 24 Hours» (havis); «You write. You get a price the same day» и «Three fields, no call» (vayle); «You get a price and a date the same working day, or an honest reason why I am not the right person for it» (vayle); «You only pay for the build if you accept the result» (schmalbach); «The quote you get is the price you pay», «You own everything», «One developer. Direct line. No agency layers.», «You get me. Not a project manager.» (havis); «I am proud to publish my rates before you have to sit through a sales call» (rob-saunders); «If another approach is better for the project, I will say so» (gittings); «When it breaks, somebody picks up» (vayle — продажа поддержки через боль). Плюс статус «Now booking · 1–2 spots» / «Currently available for new projects» и FAQ, где вопросы сформулированы как возражения: «Do I have to get on a call first?», «Who owns the domain, hosting and code?», «What if the project runs over budget?», «What is the difference between a freelance web designer and a web agency?».

## 7. Как это применить к victormatsakov.com (коротко)

- **Hero.** Формула vayle/havis: результат + срок + условие цены. Вторая строка — формат Wieruch для HR: стек | город | формат работы. Два CTA: «Рассчитать проект» (бизнес) и «Резюме / опыт» (HR) — как маршрутизатор hooley «какой разработчик вам нужен».
- **Услуги.** 4–5 офферов (сайт / магазин / веб-приложение / интеграция / поддержка), у каждого «от X», срок, «что входит», «что не входит» (vayle), и подписка на поддержку отдельной строкой (havis «Care», vayle «Essential/Growth»). Для приложений — «фикс после оценки» + вилки бюджета с примерами в форме (gajdos). Опционально входной продукт «аудит/оценка», зачитываемый в заказ (havis).
- **Кейсы.** Карточка: название + одна строка результата + 2–3 тега (vayle, set.studio). Страница: Проблема → Before/After → Что сделал → Результат + отзыв → CTA «Хотите такой же результат?» (havis). Стек — отдельной подписанной строкой «Технически» внизу (schmalbach/gajdos); аккордеон не обязателен, но допустим — никто из бенчмарка его не использует, достаточно отделить визуально.
- **HR-слой.** Один блок с табами Skills / Experience / Code (gajdos) + PDF-резюме (chiang) на отдельной странице, ссылка из hero и футера. Не смешивать с клиентскими блоками.
- **Доверие.** Именные отзывы с должностями; «Открыть сайт» / живые ссылки; процесс из 4 шагов со сроками и схемой оплаты 50/50; FAQ из 6–8 вопросов-возражений («Нужен ли созвон?», «Кому принадлежит код и домен?», «Что если проект выйдет за бюджет?», «Чем вы отличаетесь от агентства?»); статус доступности.
- **Не делать.** Повторять цифры в трёх местах; больше 5 услуг на главной; иконки-фичи; логотипы технологий вместо клиентов; «Гарантируем» без гарантии; блог/курсы выше CTA заказа.
